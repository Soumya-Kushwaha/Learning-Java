# String, StringBuilder & StringBuffer

## 1. String Basics

- `String` represents a sequence of characters.
- **Strings are immutable:** once a `String` object is created, its content cannot be changed. Operations such as concatenation or case conversion return a new string.
- `String` belongs to `java.lang`, so it does not require an explicit import.

```java
String s = "Java";
s.concat(" Programming");

System.out.println(s); // Java — original string is unchanged

s = s.concat(" Programming");
System.out.println(s); // Java Programming
```

### String Pool

The String Pool stores canonical string instances so equivalent string literals can share an object.

```java
String a = "Java";
String b = "Java";
String c = new String("Java");

System.out.println(a == b);      // true — same pooled reference
System.out.println(a == c);      // false — distinct objects
System.out.println(a.equals(c)); // true — same content
```

- String literals with the same content generally refer to the same pooled instance.
- `new String("Java")` explicitly creates a distinct `String` object.
- `==` compares object references; `equals()` compares string content.
- `intern()` returns the canonical pooled representation of a string.

```java
String s1 = new String("Java");
String s2 = s1.intern();

System.out.println(s2 == "Java"); // true
```

`intern()` does not make the original object become the pooled object; it returns the canonical reference.

### How Strings Are Stored

- Before Java 9, common OpenJDK implementations represented strings using `char[]`.
- Since Java 9, standard OpenJDK implementations use **Compact Strings**, storing data in a `byte[]` with a coder that identifies Latin-1 or UTF-16 encoding.
- Latin-1-compatible content can use one byte per character; UTF-16 content uses two bytes per UTF-16 code unit.
- `String.length()` counts UTF-16 code units, not necessarily Unicode code points or user-perceived characters.
- String hash codes may be cached as an implementation optimization; this is not a guarantee about the internal representation of every JVM.

## 2. String Methods Quick Reference

### Length & Emptiness

| Method | Description |
|---|---|
| `length()` | Returns the number of UTF-16 code units in the string. |
| `isEmpty()` | Returns `true` if the string's length is `0`. |
| `isBlank()` *(Java 11+)* | Returns `true` if the string is empty or contains only whitespace as defined by Java's whitespace rules. |

### Character Access

| Method | Description |
|---|---|
| `charAt(int index)` | Returns the UTF-16 `char` at the specified index. |
| `toCharArray()` | Returns a new character array (`char[]`) containing the string's characters. |

### Comparison

| Method | Description |
|---|---|
| `equals(Object obj)` | Checks whether two strings have the same content, considering case. |
| `equalsIgnoreCase(String another)` | Compares string content without considering case. |
| `compareTo(String another)` | Compares strings lexicographically; returns `0` if equal, a negative value if smaller, or a positive value if greater. |

### Searching

| Method | Description |
|---|---|
| `contains(CharSequence s)` | Checks whether the string contains the specified character sequence. |
| `indexOf(...)` | Returns the index of the first occurrence of a character or substring, or `-1` if not found. |
| `lastIndexOf(...)` | Returns the index of the last occurrence of a character or substring, or `-1` if not found. |
| `startsWith(String prefix)` | Checks whether the string begins with the specified prefix. |
| `endsWith(String suffix)` | Checks whether the string ends with the specified suffix. |

### Extraction

| Method | Description |
|---|---|
| `substring(int beginIndex)` | Returns the substring from `beginIndex` to the end. |
| `substring(int beginIndex, int endIndex)` | Returns the substring from `beginIndex` (inclusive) to `endIndex` (exclusive). |

### Case Conversion

| Method | Description |
|---|---|
| `toUpperCase()` | Returns a string converted to uppercase using the default locale. |
| `toLowerCase()` | Returns a string converted to lowercase using the default locale. |
| `toUpperCase(Locale locale)` | Converts to uppercase using the specified locale. |
| `toLowerCase(Locale locale)` | Converts to lowercase using the specified locale. |

Use `Locale.ROOT` for locale-independent case conversion when appropriate.

### Whitespace Handling

| Method | Description |
|---|---|
| `trim()` | Removes leading and trailing characters with code points up to U+0020. |
| `strip()` *(Java 11+)* | Removes leading and trailing Unicode whitespace as defined by `Character.isWhitespace()`. |

### Modification & Replacement

| Method | Description |
|---|---|
| `replace(char oldChar, char newChar)` | Replaces every occurrence of the specified character. |
| `replace(CharSequence target, CharSequence replacement)` | Replaces every literal occurrence of the target sequence. |
| `replaceAll(String regex, String replacement)` | Replaces every substring matching the specified regular expression. |
| `repeat(int count)` *(Java 11+)* | Returns a string formed by repeating the original string `count` times. |

These methods return a result; they do not modify the original string.

### Splitting & Joining

| Method | Description |
|---|---|
| `split(String regex)` | Splits the string around matches of a regular expression and returns a `String[]`. |
| `split(String regex, int limit)` | Splits using a regular expression, with `limit` controlling the number of results and treatment of trailing empty strings. |
| `String.join(CharSequence delimiter, CharSequence... elements)` | Joins character sequences using the specified delimiter. |
| `String.join(CharSequence delimiter, Iterable<? extends CharSequence> elements)` | Joins elements from an iterable using the specified delimiter. |

### Conversion

| Method | Description |
|---|---|
| `String.valueOf(...)` | Converts a value to its string representation. Overloads support primitives, characters, character arrays, and objects. |
| `getBytes()` | Encodes the string using the platform's default charset and returns a `byte[]`. |
| `getBytes(Charset charset)` | Encodes the string using the specified charset, such as `StandardCharsets.UTF_8`. |

Prefer `getBytes(StandardCharsets.UTF_8)` when a consistent encoding is required.

### String Pool

| Method | Description |
|---|---|
| `intern()` | Returns the canonical pooled representation of the string. If an equivalent pooled string exists, its reference is returned; otherwise, the string is added to the pool. |

### Formatting

| Method | Description |
|---|---|
| `String.format(String format, Object... args)` | Creates a formatted string using format specifiers such as `%s` (string), `%d` (integer), and `%.2f` (two decimal places). |
| `String.format(Locale locale, String format, Object... args)` | Formats a string using the specified locale. |

### Examples

```java
String s = "Java Programming";

System.out.println(s.length());                  // 16
System.out.println(s.isEmpty());                 // false
System.out.println("  ".isBlank());              // true — Java 11+
System.out.println(s.charAt(0));                 // J
System.out.println(s.substring(0, 4));            // Java
System.out.println(s.contains("Program"));        // true
System.out.println(s.indexOf("a"));               // 1
System.out.println(s.lastIndexOf("a"));           // 3
System.out.println(s.replace("Java", "Python"));  // Python Programming
System.out.println("Java".repeat(3));             // JavaJavaJava
System.out.println(String.join("-", "A", "B", "C")); // A-B-C

char[] chars = "Java".toCharArray();
byte[] bytes = "Java".getBytes(java.nio.charset.StandardCharsets.UTF_8);

String number = String.valueOf(123);               // "123"
String bool = String.valueOf(true);                // "true"
String nullText = String.valueOf((Object) null);   // "null"

String formatted = String.format(
    "Name: %s, Age: %d, Score: %.2f",
    "Sam", 24, 91.256
);
// Name: Sam, Age: 24, Score: 91.26
```

## 3. Important String Gotchas

- **`isEmpty()` vs `isBlank()`:** `isEmpty()` checks for zero length; `isBlank()` also accepts whitespace-only strings. `isBlank()` requires Java 11+.
- **`==` vs `equals()`:** `==` compares references; `equals()` compares content.
- **`split()` and `replaceAll()`:** Both use regular expressions. For example, use `split("\\.")` to split on a literal period.
- **`replace()` vs `replaceAll()`:** `replace()` performs literal replacement; `replaceAll()` treats its first argument as a regex.
- **`trim()` vs `strip()`:** `strip()` uses Java's Unicode whitespace definition; `trim()` removes characters up to U+0020 from the ends.
- **`valueOf(null)`:** `String.valueOf((Object) null)` returns `"null"`. Calling `.toString()` on a null reference throws `NullPointerException`.
- **Encoding:** `getBytes()` without a charset uses the platform default. Specify a charset for predictable results.
- **Immutability:** Methods that transform or extract text return results; the original `String` remains unchanged.
- **Indexing:** String indices refer to UTF-16 code units. Some Unicode characters, such as many emoji, occupy two code units.

## 4. String Immutability: Advantages & Trade-offs

### Advantages

- **Safe sharing:** Strings can be shared across code without another part of the program changing their content.
- **String Pool:** Immutable strings can safely be reused by multiple references.
- **Reliable hash keys:** A string's content and hash code remain stable, making strings suitable as `HashMap` keys.
- **Security and reliability:** Immutable values reduce the risk of a string changing unexpectedly after validation or when passed between components.
- **Thread safety:** A `String` can be shared between threads without synchronization for reading its content.

### Trade-offs

- **Repeated modifications create objects:** Expressions involving repeated concatenation may create intermediate strings.
- **Extra allocation in loops:** Repeated `+` concatenation inside a loop can create unnecessary temporary objects.
- **No in-place updates:** Changing content requires assigning a new string reference or using a mutable alternative.

Example of potentially inefficient repeated concatenation:

```java
String result = "";

for (int i = 0; i < 1000; i++) {
    result += i;
}
```

Prefer `StringBuilder` for repeated construction:

```java
StringBuilder result = new StringBuilder();

for (int i = 0; i < 1000; i++) {
    result.append(i);
}

String finalResult = result.toString();
```

The compiler may optimize some concatenation expressions, particularly straightforward expressions. However, `StringBuilder` is the usual choice for repeated appends in a loop.

## 5. StringBuilder vs StringBuffer

Both classes represent mutable character sequences, unlike immutable `String`.

| Feature | `String` | `StringBuilder` | `StringBuffer` |
|---|---|---|---|
| Mutability | Immutable | Mutable | Mutable |
| Thread safety | Safe to share immutable content | Not synchronized | Individual methods are synchronized |
| Performance | Can allocate new strings during repeated changes | Usually preferred for single-threaded string construction | Synchronization can add overhead |
| Typical use | Fixed text and string values | Repeated concatenation or modification | Shared mutable text requiring synchronized methods |

### StringBuilder

- Mutable and generally preferred for repeated string modifications within one thread.
- Common methods include `append()`, `insert()`, `delete()`, `replace()`, `reverse()`, `toString()`, `capacity()`, and `ensureCapacity()`.

```java
StringBuilder sb = new StringBuilder("Java");
sb.append(" Programming");
sb.insert(0, "Learn ");
sb.replace(0, 5, "Study");

System.out.println(sb); // Study Java Programming
```

### StringBuilder Capacity & Expansion

**Capacity vs length**

- **Length (`length()`):** Number of characters currently in the sequence.
- **Capacity (`capacity()`):** Amount of character storage available before expansion is needed.

Capacity can be greater than length because `StringBuilder` reserves extra storage for future additions.

#### Initial Capacity

| Initialization | Initial capacity |
|---|---:|
| `new StringBuilder()` | `16` |
| `new StringBuilder(50)` | `50` |
| `new StringBuilder("Java")` | String length + `16` = `20` |

#### Automatic Capacity Expansion

When an operation requires more capacity than is currently available, the standard implementation generally grows the capacity using:

_New Capacity = (Old Capacity + 1) * 2_

If the requested minimum capacity is larger than the calculated capacity, the implementation expands enough to accommodate that minimum.

**Example:**

```java
StringBuilder sb = new StringBuilder();

System.out.println(sb.length());   // 0
System.out.println(sb.capacity()); // 16

sb.append("Java");

System.out.println(sb.length());   // 4
System.out.println(sb.capacity()); // 16

StringBuilder text = new StringBuilder("Java");
System.out.println(text.capacity()); // 20
```

The growth formula describes common implementation behavior, not a universal API guarantee. Exact capacity after expansion can depend on the Java implementation and the requested minimum.

#### `ensureCapacity(int minimumCapacity)`

Ensures that the capacity is at least the specified minimum. If the current capacity is insufficient, the implementation can expand the buffer. This can help reduce repeated expansions when the approximate required size is known in advance.

```java
StringBuilder sb = new StringBuilder();

System.out.println(sb.capacity()); // 16

sb.ensureCapacity(50);
System.out.println(sb.capacity()); // At least 50

sb.append("Java");

System.out.println(sb.length());   // 4
System.out.println(sb.capacity()); // At least 50
```

**Important points:**

- `ensureCapacity()` does not append characters or change the current length.
- If the existing capacity is already sufficient, expansion is unnecessary.
- The resulting capacity may be larger than the requested minimum.
- Use `ensureCapacity()` when you can estimate the amount of text to be built and want to reduce repeated expansions.

### StringBuffer

- Similar to `StringBuilder`, but its methods are synchronized.
- Synchronization protects individual method calls; a sequence of multiple calls is not automatically atomic.
- Consider whether external synchronization or a different design is more appropriate when sharing mutable text between threads.

```java
StringBuffer sb = new StringBuffer("Java");
sb.append(" Programming");

System.out.println(sb); // Java Programming
```

## 6. Interview Quick Revision

- **Why is `String` immutable?** Immutability supports safe sharing, pooling, stable hash-based collections, and reliability.
- **When should you use `StringBuilder`?** For repeated string construction or modification, especially inside loops.
- **How does `StringBuffer` differ from `StringBuilder`?** `StringBuffer` synchronizes individual methods; `StringBuilder` does not.
- **Is `StringBuilder` thread-safe?** No, not by default.
- **What is the difference between length and capacity?** Length is the current number of characters; capacity is the available storage before expansion is needed.
- **What is the default `StringBuilder` capacity?** `16` when created with `new StringBuilder()`.
- **How does capacity grow?** Common implementations use `(old capacity + 1) * 2`, subject to the requested minimum; this is not an API guarantee.
- **What does `ensureCapacity()` do?** Ensures at least the requested capacity without changing the current length.
- **Does `final StringBuilder sb` make its content immutable?** No. `final` prevents reassignment of the reference, not mutation of the referenced object.
- **Does `intern()` modify a string?** No. It returns the canonical pooled reference.
- **Why specify a charset in `getBytes()`?** To avoid relying on a platform-dependent default encoding.
