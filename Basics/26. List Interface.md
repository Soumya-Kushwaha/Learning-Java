# List Interface, ArrayList & LinkedList

## 1. List Interface

`List<E>` is an ordered collection that:
- Maintains element order.
- Allows duplicate elements.
- Supports positional access using zero-based indexes.
- Allows multiple `null` elements if the implementation supports them.

`List` extends `Collection` and provides additional operations for working with elements by position.

```java
List<String> names = new ArrayList<>();

names.add("Asha");
names.add("Ravi");
names.add("Asha");

System.out.println(names); // [Asha, Ravi, Asha]
System.out.println(names.get(1)); // Ravi
```

## 2. List Hierarchy

The simplified hierarchy is:

```text
Iterable
   |
Collection
   |
SequencedCollection (Java 21+)
   |
  List
   |
   +----------------+----------------+----------------+
   |                |                |
ArrayList        LinkedList         Vector
                                      |
                                    Stack
```

### `SequencedCollection` (Java 21+)

Java 21 introduced `SequencedCollection<E>` to represent collections with a defined encounter order and provide common operations at both ends.

`List` extends `SequencedCollection`.

Important methods include:

| Method | Purpose |
|---|---|
| `addFirst(e)` | Inserts an element at the beginning |
| `addLast(e)` | Inserts an element at the end |
| `getFirst()` | Retrieves the first element |
| `getLast()` | Retrieves the last element |
| `removeFirst()` | Removes and returns the first element |
| `removeLast()` | Removes and returns the last element |
| `reversed()` | Returns a reverse-ordered view |

These methods are available through the sequenced collection hierarchy in Java 21 and later.

## 3. Common List Methods

`List` inherits common operations from `Collection` and adds positional operations.

| Method | Purpose |
|---|---|
| `add(E e)` | Appends an element |
| `add(int index, E e)` | Inserts an element at an index |
| `get(int index)` | Retrieves an element at an index |
| `set(int index, E e)` | Replaces an element at an index |
| `remove(int index)` | Removes the element at an index |
| `remove(Object o)` | Removes the first matching element |
| `indexOf(Object o)` | Returns the first matching index, or `-1` |
| `lastIndexOf(Object o)` | Returns the last matching index, or `-1` |
| `subList(int from, int to)` | Returns a view of a portion of the list |
| `listIterator()` | Returns a bidirectional list iterator |

### 3.1 Adding elements

```java
List<String> names = new ArrayList<>();

names.add("Asha");        // Appends
names.add("Maya");        // Appends
names.add(1, "Ravi");     // Inserts at index 1

System.out.println(names); // [Asha, Ravi, Maya]
```

When inserting at an index, existing elements at that position and after it shift to the right.

### 3.2 Accessing and replacing elements

```java
System.out.println(names.get(1)); // Ravi

names.set(1, "Neha");

System.out.println(names); // [Asha, Neha, Maya]
```

`set()` replaces an existing element; it does not increase the list size.

### 3.3 Removing elements

```java
List<Integer> numbers = new ArrayList<>(
    Arrays.asList(10, 20, 30, 20)
);

numbers.remove(1);                   // Removes element at index 1
numbers.remove(Integer.valueOf(20)); // Removes first matching value

System.out.println(numbers); // [10, 20]
```

**Important overload distinction:**
- `remove(int index)` removes by position.
- `remove(Object o)` removes by value.

### 3.4 Searching

```java
List<String> names = Arrays.asList("Asha", "Ravi", "Maya", "Ravi");

System.out.println(names.indexOf("Ravi"));     // 1
System.out.println(names.lastIndexOf("Ravi")); // 3
System.out.println(names.indexOf("Neha"));     // -1
```

### 3.5 `subList()`

Returns a view of the specified range, from `fromIndex` (inclusive) to `toIndex` (exclusive).

```java
List<Integer> numbers = new ArrayList<>(
    Arrays.asList(10, 20, 30, 40, 50)
);

List<Integer> part = numbers.subList(1, 4);

System.out.println(part); // [20, 30, 40]
```

**Important:** `subList()` returns a view backed by the original list, not an independent copy. Changes through the view affect the original list. Structural modifications to the backing list outside the view can make the view's behavior undefined.

## 4. ListIterator

`ListIterator<E>` extends `Iterator<E>` and supports bidirectional traversal and list-specific modification operations.

Unlike a regular `Iterator`, it can move both forward and backward.

| Method | Purpose |
|---|---|
| `hasNext()` | Checks whether a next element exists |
| `next()` | Returns the next element |
| `hasPrevious()` | Checks whether a previous element exists |
| `previous()` | Returns the previous element |
| `nextIndex()` | Returns the index of the next element |
| `previousIndex()` | Returns the index of the previous element |
| `add(E e)` | Inserts an element at the iterator's current position |
| `set(E e)` | Replaces the last element returned by `next()` or `previous()` |
| `remove()` | Removes the last element returned by `next()` or `previous()` |

### Example: Forward and backward traversal

```java
List<String> names = new ArrayList<>(
    Arrays.asList("Asha", "Ravi", "Maya")
);

ListIterator<String> iterator = names.listIterator();

while (iterator.hasNext()) {
    System.out.println(iterator.next());
}

// Move backward
while (iterator.hasPrevious()) {
    System.out.println(iterator.previous());
}
```

The iterator starts before the first element. After forward traversal reaches the end, backward traversal can move through the elements in reverse order.

### `Iterator` vs `ListIterator`

| Iterator | ListIterator |
|---|---|
| Forward traversal | Forward and backward traversal |
| Works with collections generally | Available for lists |
| `hasNext()`, `next()` | Also provides `hasPrevious()`, `previous()` |
| Supports optional `remove()` | Supports optional `remove()`, `add()`, and `set()` |
| No index methods | Provides `nextIndex()` and `previousIndex()` |

## 5. ArrayList

`ArrayList<E>` is a resizable-array implementation of the `List` interface.

Internally, it uses an array to store elements. When its capacity is insufficient, it creates a larger array and copies the existing elements.

### Characteristics

- Maintains insertion order.
- Allows duplicates and `null` values.
- Provides fast indexed access.
- Insertion or deletion in the middle requires shifting elements.
- Not synchronized by default.

### Time Complexity

| Operation | Typical complexity |
|---|---:|
| `get(index)` | \(O(1)\) |
| `set(index, element)` | \(O(1)\) |
| Append using `add(element)` | Amortized \(O(1)\) |
| Insert at a position | \(O(n)\) |
| Remove at a position | \(O(n)\) |
| Search using `contains()` | \(O(n)\) |

### Dynamic resizing

When the internal array becomes full, `ArrayList` allocates a larger array and copies existing elements.

In commonly used OpenJDK implementations, growth is approximately 1.5 times the old capacity:

\[
\text{New capacity} \approx \text{Old capacity} + \frac{\text{Old capacity}}{2}
\]

This is an implementation detail, not a guaranteed API contract.

### Example

```java
List<Integer> numbers = new ArrayList<>();

numbers.add(10);
numbers.add(20);
numbers.add(30);

System.out.println(numbers.get(1)); // 20

numbers.add(1, 15);

System.out.println(numbers); // [10, 15, 20, 30]
```

**When to use:** When indexed access and iteration are frequent, and insertions or deletions in the middle are relatively uncommon.

## 6. LinkedList

`LinkedList<E>` is a doubly linked list implementation of both `List` and `Deque`.

Each node stores:
- The element.
- A reference to the previous node.
- A reference to the next node.

The list maintains references to its first and last nodes.

### Characteristics

- Maintains insertion order.
- Allows duplicates and `null` values.
- Does not provide efficient random access.
- Supports efficient insertion and removal at both ends.
- Can insert or remove elements efficiently when the relevant position is already reached.
- Not synchronized by default.

### Internal structure

Conceptually:

```text
null <- [10] <-> [20] <-> [30] -> null
         first              last
```

Each node is linked to its previous and next node.

### Time Complexity

| Operation | Typical complexity |
|---|---:|
| `get(index)` | \(O(n)\) |
| `set(index, element)` | \(O(n)\) |
| `addFirst()` / `addLast()` | \(O(1)\) |
| `removeFirst()` / `removeLast()` | \(O(1)\) |
| Insert/remove through an already positioned iterator | \(O(1)\) |
| Search using `contains()` | \(O(n)\) |

For indexed operations, `LinkedList` traverses from whichever end is closer, but the operation remains \(O(n)\) in the general case.

### Example

```java
LinkedList<Integer> numbers = new LinkedList<>();

numbers.add(10);
numbers.add(20);
numbers.add(30);

numbers.addFirst(5);
numbers.addLast(40);

System.out.println(numbers); // [5, 10, 20, 30, 40]

numbers.removeFirst();
numbers.removeLast();

System.out.println(numbers); // [10, 20, 30]
```

**When to use:** When frequent insertion and removal at the beginning or end are needed, or when using deque operations. It is not generally a better choice than `ArrayList` for ordinary list usage.

## 7. ArrayList vs LinkedList

| Feature | ArrayList | LinkedList |
|---|---|---|
| Internal structure | Dynamic array | Doubly linked list |
| Random access | \(O(1)\) | \(O(n)\) |
| Append | Amortized \(O(1)\) | \(O(1)\) |
| Insert/remove at beginning | \(O(n)\) | \(O(1)\) |
| Insert/remove at middle | \(O(n)\) due to shifting | \(O(n)\) to reach position; \(O(1)\) to update links |
| Memory overhead | Lower | Higher due to node references |
| Cache locality | Generally better | Generally poorer |
| Implements `List` | Yes | Yes |
| Implements `Deque` | No | Yes |

**Practical takeaway:** Prefer `ArrayList` as the default general-purpose list. Choose `LinkedList` when its end operations or deque behavior are specifically useful; do not assume it is faster for every insertion or deletion.

## 8. Legacy Classes: Vector and Stack

### 8.1 Vector

`Vector<E>` is a legacy resizable-array implementation of `List`.

Characteristics:
- Similar to `ArrayList`.
- Its individual methods are synchronized.
- Supports dynamic resizing.
- Has legacy methods such as `addElement()` and `elementAt()`.

Because its methods are synchronized, it can introduce synchronization overhead when thread safety is not required.

### 8.2 Stack

`Stack<E>` is a legacy class that extends `Vector<E>` and provides LIFO stack operations.

Important methods:

| Method | Purpose |
|---|---|
| `push(E item)` | Pushes an element onto the stack |
| `pop()` | Removes and returns the top element |
| `peek()` | Returns the top element without removing it |
| `empty()` | Checks whether the stack is empty |
| `search(Object o)` | Returns the 1-based position from the top, or `-1` if absent |

`Stack` inherits other `Vector` operations as well, so it is not a particularly clean stack abstraction.

### Modern alternative: ArrayDeque

For ordinary single-threaded stack behavior, Java generally recommends `Deque` implementations such as `ArrayDeque` instead of legacy `Stack`.

```java
Deque<Integer> stack = new ArrayDeque<>();

stack.push(10);
stack.push(20);

System.out.println(stack.peek()); // 20
System.out.println(stack.pop());  // 20
System.out.println(stack.pop());  // 10
```

`ArrayDeque` is not thread-safe and does not permit `null` elements.

### Vector vs ArrayList

| Feature | ArrayList | Vector |
|---|---|---|
| Internal structure | Dynamic array | Dynamic array |
| Synchronization | Not synchronized | Individual methods synchronized |
| Performance | Generally less synchronization overhead | Synchronization overhead |
| Status | Common modern choice | Legacy class |

**Note:** Synchronizing individual methods does not automatically make a multi-operation sequence atomic or make all compound access patterns thread-safe.

## 9. Interview Quick Revision

1. **What is `List`?** An ordered collection that permits duplicates and supports index-based access.
2. **What is `SequencedCollection`?** A Java 21 interface that provides a common contract for collections with encounter order and operations at both ends.
3. **`add()` vs `set()`?** `add()` inserts an element; `set()` replaces an existing element.
4. **`remove(1)` vs `remove(Integer.valueOf(1))`?** The first removes index 1; the second removes the matching value 1.
5. **What is `ListIterator`?** A bidirectional iterator that also supports list-specific operations.
6. **How does `ArrayList` work internally?** It uses a resizable array.
7. **What is the growth factor of `ArrayList`?** Common OpenJDK implementations grow by approximately 1.5 times; this is not an API guarantee.
8. **How does `LinkedList` work internally?** It uses doubly linked nodes.
9. **Why is `get(index)` slower in `LinkedList`?** It must traverse nodes to reach the requested position.
10. **Is insertion in the middle always \(O(1)\) in `LinkedList`?** No. Finding the position is generally \(O(n)\); link updates are \(O(1)\) once positioned.
11. **Why prefer `ArrayDeque` over `Stack`?** `ArrayDeque` provides modern deque-based stack operations without the legacy `Vector` inheritance and synchronization overhead.
12. **Which should generally be preferred: `ArrayList` or `LinkedList`?** `ArrayList` for general-purpose list usage, unless a specific `LinkedList`/`Deque` operation justifies the latter.
