# Classes & Objects

## Procedural vs. Object-Oriented Programming
- **Procedural programming:** Organizes code around procedures/functions and separate data.
- **OOP:** Groups related state (fields) and behavior (methods) into objects.
- OOP helps organize and model complex entities; it does not eliminate the need for functions or procedural logic.

## Classes & Objects
- **Class:** Defines the structure and behavior of objects.
- **Object:** A runtime instance of a class with its own instance state.
- Objects can model physical entities (e.g., `Student`) or conceptual entities (e.g., `BankAccount`).

## Fields & Methods
- **Fields:** Store object state/characteristics.
- **Methods:** Define behavior or operations.
- Instance fields belong to each object; static fields belong to the class.

## Creating Objects
```java
class Student {
    String name;
    int age;

    void display() {
        System.out.println(name + " " + age);
    }
}

public class Main {
    public static void main(String[] args) {
        Student s1 = new Student();
        s1.name = "Asha";
        s1.age = 22;

        Student s2 = new Student();
        s2.name = "Ravi";
        s2.age = 24;

        s1.display();
        s2.display();
    }
}
```

- `new` creates an object and invokes its constructor.
- The object is ordinarily allocated on the heap; the reference is stored in `s1` or `s2`.
- Each instance has its own instance fields.
- The dot operator (`.`) accesses members through a reference, e.g. `s1.name` or `s1.display()`.

## Naming Conventions
- Classes: `PascalCase` — `BankAccount`
- Variables and methods: `camelCase` — `accountBalance`, `deposit()`
- Constants: typically `UPPER_SNAKE_CASE` — `MAX_LIMIT`

## Key Points
- A class is a type/definition; an object is an instance.
- Multiple objects can be created from one class.
- A reference variable does not itself contain the entire object.
