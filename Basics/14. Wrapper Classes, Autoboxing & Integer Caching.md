# Wrapper Classes, Autoboxing & Integer Caching

## Wrapper Classes
Wrapper classes represent primitive values as objects.

| Primitive | Wrapper |
|---|---|
| `byte` | `Byte` |
| `short` | `Short` |
| `int` | `Integer` |
| `long` | `Long` |
| `float` | `Float` |
| `double` | `Double` |
| `char` | `Character` |
| `boolean` | `Boolean` |

Useful when working with collections such as `List<Integer>`, which cannot store primitive types directly.

## Autoboxing & Unboxing
- **Autoboxing:** Primitive → wrapper object.
- **Unboxing:** Wrapper object → primitive.

```java
Integer a = 10;  // Autoboxing
int b = a;       // Unboxing
```

Unboxing `null` throws `NullPointerException`.

```java
Integer value = null;
// int n = value; // NullPointerException
```

## Comparing Wrapper Objects
- `==` compares primitive values when both operands are primitives.
- For wrapper references, `==` compares object identity.
- `.equals()` compares wrapper values when both references are non-null.

```java
Integer a = 100;
Integer b = 100;
System.out.println(a == b);      // true: cached value
System.out.println(a.equals(b)); // true: equal values
```

## Integer Caching
- Java guarantees caching for boxed constant values from `-128` through `127`.
- Some implementations may cache additional values.
- Consequently, `==` can appear to work for some boxed integers but fail for others.

```java
Integer x = 100;
Integer y = 100;

System.out.println(x == y);      // Typically false, but true, in this case
System.out.println(x.equals(y)); // true
```

## Best Practices
- Use `.equals()` to compare wrapper values, with null handling where necessary.
- Use `Objects.equals(a, b)` for null-safe equality checks.
- Use primitives when object semantics or `null` are not required.
- Avoid unnecessary boxing and unboxing in performance-sensitive code.
- Wrapper classes are immutable.
