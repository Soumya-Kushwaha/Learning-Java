# POJO (Plain Old Java Object)
- A POJO is a simple Java object that is not required to extend a framework-specific base class or implement framework-specific interfaces.
- **POJO** describes a style of Java object.
- A POJO can be a concrete class; an abstract class is not automatically a POJO or non-POJO.

Common characteristics:
- Models data or domain concepts.
- Often contains fields, constructors, and methods.
- May provide getters/setters, but these are not mandatory.
- Can contain business logic; a POJO is not necessarily a data-only class.

## Anemic vs. Rich Domain Model
- **Anemic model:** Primarily stores data; business logic lives elsewhere, often in service classes.
- **Rich domain model:** Encapsulates relevant business rules and behavior within domain objects.

Neither approach is universally correct. The appropriate design depends on the application's complexity and architecture.
