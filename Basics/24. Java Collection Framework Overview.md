# Java Collection Framework — Overview

## 1. Why Do We Need Data Structures?

A **data structure** organizes and stores data so that operations such as insertion, deletion, searching, and traversal can be performed efficiently.

Different data structures optimize different operations. Choosing the right one depends on how the data will be used.

For example:
- Searching for an element in an unsorted array may require checking every element.
- A set helps maintain unique elements and supports efficient membership checks.
- A map stores key-value pairs for looking up a value using its key.
- A queue processes elements in FIFO order.

## 2. Common Data Structures

### 2.1 Arrays

An array stores elements of the same declared component type in indexed positions. In Java, an array has a fixed length after creation.

```java
int[] numbers = {10, 20, 30, 40};
System.out.println(numbers[2]); // 30
```

**Characteristics**
- Access by index: \(O(1)\).
- Searching an unsorted array: \(O(n)\) in the worst case.
- Fixed length after creation.
- Inserting or deleting in the middle generally requires shifting elements.

### 2.2 Dynamic Arrays

A dynamic array manages a resizable array internally. When its capacity is insufficient, it can allocate a larger array and copy elements.

Java's `ArrayList` is a common example.

**Characteristics**
- Fast indexed access: \(O(1)\).
- Appending is amortized \(O(1)\).
- Inserting or deleting in the middle is generally \(O(n)\), due to shifting.
- Size can grow or shrink as elements are added or removed.

### 2.3 Linked Lists

A linked list consists of nodes. Each node stores an element and one or more links to other nodes.

In a singly linked list, each node points to the next node. In a doubly linked list, nodes link to both the previous and next nodes.

**Characteristics**
- Accessing an element by index takes \(O(n)\).
- Insertion or deletion can be \(O(1)\) when the relevant node or position is already known and the required links can be updated directly.
- Finding the position first can take \(O(n)\).
- Nodes require additional memory for links.

### 2.4 Sets

A set stores **unique elements**; duplicate elements are not retained as separate entries.

```java
Set<Integer> numbers = new HashSet<>();

numbers.add(10);
numbers.add(20);
numbers.add(10); // Duplicate; set still contains only one 10
```

**Characteristics**
- Useful for uniqueness and membership checks.
- `HashSet` uses hashing and typically provides expected \(O(1)\) insertion, deletion, and lookup, assuming a good hash distribution.
- `TreeSet` maintains elements in sorted order and typically provides \(O(\log n)\) basic operations.

### 2.5 Stacks

A stack follows **LIFO — Last In, First Out**. The last element added is the first one removed.

Typical operations:
- `push()` — add an element.
- `pop()` — remove and return the top element.
- `peek()` — inspect the top element without removing it.

Common applications include function-call management, undo operations, and expression evaluation.

### 2.6 Queues

A queue commonly follows **FIFO — First In, First Out**. The first element added is the first one removed.

Typical operations:
- `offer()` — add an element.
- `poll()` — retrieve and remove the head, or return `null` if empty.
- `peek()` — inspect the head without removing it, or return `null` if empty.

Queues are useful for task scheduling, request processing, and breadth-first search. Not every queue is strictly FIFO; a `PriorityQueue`, for example, orders elements according to priority.

### 2.7 Maps

A map stores **key-value pairs**. Each key is unique within the map and maps to at most one value.

```java
Map<Integer, String> students = new HashMap<>();

students.put(101, "Asha");
students.put(102, "Ravi");
students.put(101, "Maya"); // Replaces the value associated with key 101
```

**Characteristics**
- Lookup is performed using a key.
- In a `HashMap`, basic operations typically have expected \(O(1)\) time complexity under suitable hashing conditions.
- A `TreeMap` maintains keys in sorted order and typically provides \(O(\log n)\) basic operations.
- Multiple keys may map to equal values, but a key cannot occur more than once.

### 2.8 Trees

A tree is a hierarchical data structure made of nodes connected by parent-child relationships.

A **Binary Search Tree (BST)** is a binary tree organized by an ordering rule: values in the left subtree are smaller than the node's value, and values in the right subtree are larger, assuming distinct keys and this convention.

- Search, insertion, and deletion take \(O(\log n)\) on a reasonably balanced BST.
- These operations can degrade to \(O(n)\) in a highly skewed BST.
- Balanced trees maintain height constraints to provide predictable logarithmic operations.

Java's `TreeMap` and `TreeSet` use balanced-tree implementations to maintain sorted keys or elements.

## 3. Time Complexity — Basic Intuition

Big-O notation describes how an operation's resource requirements grow as the input size \(n\) increases.

| Complexity | Meaning | Example |
|---|---|---|
| \(O(1)\) | Constant time | Array access by index |
| \(O(\log n)\) | Logarithmic growth | Search in a balanced BST |
| \(O(n)\) | Linear growth | Scan an unsorted array |
| \(O(n \log n)\) | Linearithmic growth | Typical efficient comparison sorting |

These are common complexity patterns, not guarantees for every implementation or input. Actual performance depends on the operation, data structure, and conditions.

## 4. What Is the Java Collections Framework?

The **Java Collections Framework (JCF)** is a set of interfaces, implementations, and algorithms for representing and manipulating groups of objects.

It provides:
- **Interfaces** that define contracts, such as `List`, `Set`, and `Queue`.
- **Implementations** that provide concrete behavior, such as `ArrayList`, `HashSet`, and `PriorityQueue`.
- **Algorithms and utilities**, including sorting and searching methods in `Collections`.

The framework uses interfaces, inheritance, and polymorphism so that code can depend on a general contract rather than a particular implementation.

For example:

```java
List<String> names = new ArrayList<>();
names.add("Asha");
names.add("Ravi");
```

The variable is declared using the `List` interface, while the object created is an `ArrayList`. Another suitable `List` implementation can often be substituted without changing code that relies only on the `List` contract.

## 5. Java Collections Framework Hierarchy

The simplified hierarchy is:

```text
Iterable
   |
Collection
   |
   +------------------+------------------+
   |                  |                  |
  List               Set               Queue
   |                  |                  |
ArrayList           HashSet          PriorityQueue
LinkedList          LinkedHashSet    ArrayDeque
Vector              TreeSet          LinkedList
   |
 Stack (legacy class extending Vector)


Map  (separate from Collection)
 |
 +------------------+------------------+
 |                  |                  |
HashMap           SortedMap           Other Map implementations
                     |
                  NavigableMap
                     |
                  TreeMap
```

This is a simplified view of commonly used types, not the complete inheritance tree. For example, `LinkedHashMap`, `EnumMap`, and `IdentityHashMap` are also `Map` implementations. `LinkedList` implements both `List` and `Deque`, and `Deque` extends `Queue`.

### Key interfaces

| Interface | Purpose |
|---|---|
| `Iterable<E>` | Enables iteration, including the enhanced `for` loop |
| `Collection<E>` | Root interface for groups of elements |
| `List<E>` | Ordered sequence; permits duplicates |
| `Set<E>` | Does not permit duplicate elements |
| `Queue<E>` | Holds elements for processing, commonly in FIFO order |
| `Deque<E>` | Supports insertion and removal at both ends |
| `Map<K, V>` | Maps unique keys to values; does not extend `Collection` |

### Important distinction: `Collection` vs `Collections`

- **`Collection`** is an interface representing a group of elements.
- **`Collections`** is a utility class containing static methods for operations such as sorting, searching, and creating wrappers around collections.

They are different types with different purposes.

### Why is `Map` separate?

`List`, `Set`, and `Queue` represent groups of individual elements through the `Collection` interface.

A `Map`, by contrast, represents mappings from keys to values. It therefore belongs to the Collections Framework but does **not** extend `Collection`.

## 6. Quick Revision — Interview Points

1. **Array vs `ArrayList`:** Arrays have fixed length; `ArrayList` can resize.
2. **`ArrayList` vs `LinkedList`:** `ArrayList` supports fast indexed access; `LinkedList` supports efficient local link updates when the relevant position is already known.
3. **List vs Set:** A list permits duplicates; a set does not.
4. **Stack vs Queue:** Stack is LIFO; a conventional queue is FIFO.
5. **Set vs Map:** A set stores unique elements; a map stores key-value mappings with unique keys.
6. **`HashSet` vs `TreeSet`:** Hash-based storage versus sorted, tree-based storage.
7. **`Collection` vs `Collections`:** Interface versus utility class.
8. **Is `Map` a subtype of `Collection`?** No.
9. **Why declare a variable as an interface?** It reduces coupling to a specific implementation and supports polymorphism.
10. **Does a BST always guarantee \(O(\log n)\) operations?** No. An ordinary unbalanced BST can degrade to \(O(n)\).
