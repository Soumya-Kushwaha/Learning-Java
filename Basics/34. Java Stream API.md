# Java Stream API

Introduced in Java 8, the Stream API provides a declarative way to process sequences of data.

Instead of manually controlling iteration with loops, we describe the operations to perform on the data.

**Important:** A Stream is not a data structure. It does not store elements; it processes elements from a source.

## 1. Imperative vs Declarative

**Imperative approach:** Describe how to perform the operation.

```java
List<Integer> numbers = List.of(1, 2, 3, 4, 5);

List<Integer> evenNumbers = new ArrayList<>();

for (int number : numbers) {
    if (number % 2 == 0) {
        evenNumbers.add(number);
    }
}
```

**Declarative approach:** Describe what operation is required.

```java
List<Integer> evenNumbers = numbers.stream()
        .filter(number -> number % 2 == 0)
        .toList();
```

The Stream API makes data-processing logic more concise and composable.

## 2. Stream Pipeline

A Stream pipeline consists of three parts:

1. **Source:** Where data comes from.
2. **Intermediate operations:** Transform or filter elements.
3. **Terminal operation:** Triggers execution and produces a result or side effect.

```java
List<Integer> result = numbers.stream()       // Source
        .filter(n -> n % 2 == 0)              // Intermediate
        .map(n -> n * n)                      // Intermediate
        .toList();                            // Terminal
```

Output:

```text
[4, 16]
```

## 3. Creating Streams

### From a Collection

```java
List<String> names = List.of("Aman", "Riya");

Stream<String> stream = names.stream();
```

For parallel processing:

```java
Stream<String> parallelStream = names.parallelStream();
```

### From an Array

```java
int[] numbers = {1, 2, 3, 4};

IntStream stream = Arrays.stream(numbers);
```

For an object array:

```java
String[] names = {"Aman", "Riya"};

Stream<String> stream = Arrays.stream(names);
```

### Using Stream.of()

```java
Stream<Integer> stream = Stream.of(1, 2, 3, 4);
```

### Using Stream.empty()

```java
Stream<String> empty = Stream.empty();
```

### Infinite Streams

`Stream.generate()` repeatedly obtains elements from a `Supplier`.

```java
Stream<Double> randomNumbers = Stream.generate(Math::random);
```

`Stream.iterate()` generates elements using a seed and a function.

```java
Stream<Integer> numbers = Stream.iterate(
        1,
        n -> n + 1
);
```

These streams are infinite unless limited or otherwise short-circuited.

```java
List<Integer> firstFive = Stream.iterate(1, n -> n + 1)
        .limit(5)
        .toList();
```

Java 9+ also supports a predicate-based `iterate()` overload:

```java
Stream.iterate(1, n -> n <= 5, n -> n + 1);
```

## 4. Lazy Evaluation

Intermediate operations are **lazy**. They do not process elements immediately.

```java
Stream<Integer> stream = numbers.stream()
        .filter(n -> {
            System.out.println("Filtering: " + n);
            return n % 2 == 0;
        });
```

Nothing is printed because no terminal operation has been invoked.

Execution starts when a terminal operation is called:

```java
stream.forEach(System.out::println);
```

Benefits:
- Avoids unnecessary processing.
- Allows operations to be fused into a pipeline.
- Enables short-circuiting.

A stream is generally consumed only once. Reusing an already-consumed stream results in `IllegalStateException`.

## 5. Intermediate Operations

Intermediate operations return another Stream and are generally lazy.

### filter()

Selects elements that satisfy a condition.

```java
numbers.stream()
       .filter(n -> n > 10);
```

Takes a `Predicate<T>`.

### map()

Transforms each element into another value.

```java
List<String> names = List.of("aman", "riya");

List<String> upperCaseNames = names.stream()
        .map(String::toUpperCase)
        .toList();
```

Takes a `Function<T, R>`.

### flatMap()

Transforms each element into a stream and flattens the resulting streams into one stream.

```java
List<List<Integer>> nested = List.of(
        List.of(1, 2),
        List.of(3, 4)
);

List<Integer> flattened = nested.stream()
        .flatMap(List::stream)
        .toList();
```

Output:

```text
[1, 2, 3, 4]
```

**map vs flatMap**

| map() | flatMap() |
|---|---|
| One input produces one output value | One input produces a stream of values |
| Can produce nested structures | Flattens nested streams |
| `Function<T, R>` | `Function<T, Stream<R>>` conceptually |

### distinct()

Removes duplicate elements using equality semantics.

```java
List<Integer> unique = numbers.stream()
        .distinct()
        .toList();
```

For custom objects, correct `equals()` and `hashCode()` implementations matter.

### sorted()

Sorts elements.

```java
numbers.stream()
       .sorted()
       .toList();
```

Custom sorting:

```java
employees.stream()
        .sorted(Comparator.comparing(Employee::getName))
        .toList();
```

`sorted()` is stateful because it generally needs to see all relevant elements before producing sorted output.

### limit() and skip()

```java
numbers.stream()
       .limit(3)
       .toList();

numbers.stream()
       .skip(2)
       .toList();
```

- `limit(n)` retains at most the first `n` elements.
- `skip(n)` skips the first `n` elements.

### peek()

Allows an action to observe elements as they pass through a pipeline. Commonly used for debugging.

```java
numbers.stream()
        .peek(n -> System.out.println("Before: " + n))
        .filter(n -> n % 2 == 0)
        .peek(n -> System.out.println("After: " + n))
        .toList();
```

Do not use `peek()` for essential business logic or required side effects. Pipeline optimizations can affect whether an intermediate action executes.

## 6. Terminal Operations

Terminal operations trigger pipeline execution.

### forEach()

Performs an action for each element.

```java
numbers.stream()
       .forEach(System.out::println);
```

`forEachOrdered()` preserves encounter order when one exists, including in parallel pipelines, though it may reduce parallel performance.

### toList() and collect()

Collect results into a collection.

```java
List<Integer> result = numbers.stream()
        .filter(n -> n > 2)
        .toList();
```

Using Collectors:

```java
List<Integer> result = numbers.stream()
        .filter(n -> n > 2)
        .collect(Collectors.toList());
```

Important difference:

- `Stream.toList()` (Java 16+) returns an unmodifiable list.
- `Collectors.toList()` does not guarantee a particular list implementation or mutability.
- `Collectors.toCollection(ArrayList::new)` explicitly requests an `ArrayList`.

### count()

Returns the number of elements as a `long`.

```java
long count = numbers.stream()
        .filter(n -> n > 2)
        .count();
```

### reduce()

Combines elements into a single result.

```java
int sum = numbers.stream()
        .reduce(0, Integer::sum);
```

Another example:

```java
Optional<Integer> maximum = numbers.stream()
        .reduce(Integer::max);
```

The identity value is returned for an empty stream in the overload that accepts an identity.

For parallel reduction, the accumulator and combiner must satisfy the required associative and identity rules.

### Matching Operations

| Method | Meaning |
|---|---|
| `anyMatch()` | At least one element matches |
| `allMatch()` | Every element matches |
| `noneMatch()` | No element matches |

```java
boolean hasEven = numbers.stream()
        .anyMatch(n -> n % 2 == 0);

boolean allPositive = numbers.stream()
        .allMatch(n -> n > 0);

boolean noNegative = numbers.stream()
        .noneMatch(n -> n < 0);
```

These operations short-circuit when the result is determined.

### Searching Operations

```java
Optional<Integer> first = numbers.stream()
        .filter(n -> n > 3)
        .findFirst();

Optional<Integer> any = numbers.stream()
        .filter(n -> n > 3)
        .findAny();
```

- `findFirst()` returns the first element according to encounter order, if one exists.
- `findAny()` may return any matching element and is useful when working with parallel streams.

Both return `Optional<T>` because a matching element may not exist.

## 7. Collectors Utility Class

`Collectors` provides ready-made collectors for terminal `collect()` operations.

### toList(), toSet(), toCollection()

```java
List<Integer> list = numbers.stream()
        .collect(Collectors.toList());

Set<Integer> set = numbers.stream()
        .collect(Collectors.toSet());

ArrayList<Integer> arrayList = numbers.stream()
        .collect(Collectors.toCollection(ArrayList::new));
```

### toMap()

Convert stream elements into a Map.

```java
Map<Integer, String> map = employees.stream()
        .collect(Collectors.toMap(
                Employee::getId,
                Employee::getName
        ));
```

If two elements produce the same key, this overload throws `IllegalStateException`.

Provide a merge function to handle duplicate keys:

```java
Map<String, Integer> counts = words.stream()
        .collect(Collectors.toMap(
                word -> word,
                word -> 1,
                Integer::sum
        ));
```

### groupingBy()

Groups elements based on a classification function.

```java
Map<String, List<Employee>> byDepartment =
        employees.stream()
                .collect(Collectors.groupingBy(Employee::getDepartment));
```

Result:

```text
{
    "IT" -> [Employee1, Employee2],
    "HR" -> [Employee3]
}
```

Grouping with counting:

```java
Map<String, Long> countByDepartment =
        employees.stream()
                .collect(Collectors.groupingBy(
                        Employee::getDepartment,
                        Collectors.counting()
                ));
```

### partitioningBy()

Partitions elements into exactly two groups based on a predicate.

```java
Map<Boolean, List<Integer>> partitioned =
        numbers.stream()
                .collect(Collectors.partitioningBy(n -> n % 2 == 0));
```

- `true` key: matching elements.
- `false` key: non-matching elements.

### joining()

Concatenates string elements.

```java
String result = names.stream()
        .collect(Collectors.joining(", "));
```

With prefix and suffix:

```java
String result = names.stream()
        .collect(Collectors.joining(", ", "[", "]"));
```

### Other useful collectors

```java
// Count elements
long count = employees.stream()
        .collect(Collectors.counting());

// Sum integer values
int totalSalary = employees.stream()
        .collect(Collectors.summingInt(Employee::getSalary));

// Average
double averageSalary = employees.stream()
        .collect(Collectors.averagingInt(Employee::getSalary));

// Minimum / maximum
Optional<Employee> highestPaid = employees.stream()
        .collect(Collectors.maxBy(
                Comparator.comparingInt(Employee::getSalary)
        ));
```

## 8. Primitive Streams

Generic streams use wrapper types when processing primitive values.

```java
Stream<Integer> numbers = Stream.of(1, 2, 3);
```

Java provides specialized primitive streams to reduce boxing and unboxing:

- `IntStream`
- `LongStream`
- `DoubleStream`

Example:

```java
IntStream numbers = IntStream.range(1, 5);
```

`range(1, 5)` produces:

```text
1, 2, 3, 4
```

`rangeClosed(1, 5)` includes the upper bound:

```text
1, 2, 3, 4, 5
```

Useful operations:

```java
int sum = IntStream.rangeClosed(1, 5).sum();

OptionalInt max = IntStream.of(10, 20, 30).max();

double average = IntStream.of(10, 20, 30).average().orElse(0.0);
```

### Converting Between Stream Types

Object stream to primitive stream:

```java
int sum = employees.stream()
        .mapToInt(Employee::getSalary)
        .sum();
```

Primitive stream to object stream:

```java
List<Integer> numbers = IntStream.rangeClosed(1, 5)
        .boxed()
        .toList();
```

Other conversion methods include:
- `mapToLong()`
- `mapToDouble()`
- `asLongStream()`
- `asDoubleStream()`

## 9. Important Stream Rules and Gotchas

- A stream does not store data; it processes data from a source.
- A stream cannot normally be reused after a terminal operation.
- Intermediate operations are lazy.
- A terminal operation triggers pipeline execution.
- Avoid modifying the source collection while processing its stream.
- Avoid shared mutable state inside stream operations.
- `sorted()` and `distinct()` are stateful intermediate operations.
- `findFirst()`, `findAny()`, `anyMatch()`, `allMatch()`, and `noneMatch()` can short-circuit.
- `peek()` is primarily useful for debugging.
- Streams do not automatically make processing parallel.
- `Stream.toList()` returns an unmodifiable list.

## 10. Interview Quick Revision

**What is a Stream?**

A sequence of elements supporting declarative, functional-style data processing. It does not store the elements itself.

**What are the three parts of a Stream pipeline?**

Source, intermediate operations, and terminal operation.

**What is lazy evaluation?**

Intermediate operations execute only when a terminal operation triggers the pipeline.

**Difference between map() and flatMap()?**

`map()` transforms each element. `flatMap()` transforms elements into streams and flattens them.

**Difference between reduce() and collect()?**

`reduce()` combines elements into a single result. `collect()` performs a mutable reduction or other collection operation using a collector.

**Difference between groupingBy() and partitioningBy()?**

`groupingBy()` can create multiple groups based on a classification key. `partitioningBy()` creates two groups based on a boolean predicate.

**Difference between findFirst() and findAny()?**

`findFirst()` respects encounter order. `findAny()` may return any matching element.

**Why use IntStream instead of Stream<Integer>?**

To avoid unnecessary boxing and unboxing and to access primitive-specific operations such as `sum()` and `average()`.

### Quick Revision

- Source → Intermediate operations → Terminal operation.
- Intermediate operations are lazy.
- Terminal operations trigger execution.
- `filter()` selects; `map()` transforms; `flatMap()` flattens.
- `reduce()` combines; `collect()` gathers.
- `groupingBy()` creates groups; `partitioningBy()` creates two partitions.
- `IntStream`, `LongStream`, `DoubleStream` support primitive processing.
- Streams are single-use.
