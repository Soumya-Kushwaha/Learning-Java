# Object Memory & Copying

## Object Memory Layout
An object's memory commonly includes:
- **Object header:** JVM metadata; exact contents depend on the JVM.
- **Instance fields:** Object state, including primitive values and reference values.
- **Padding:** Alignment added according to the JVM's object-layout rules.

- Exact object size depends on JVM implementation, object layout, field types, alignment, and runtime configuration.
- Use tools such as Java Object Layout (JOL) when actual object-size measurements are needed.

## Java Is Pass-by-Value
Java always passes arguments by value.

- **Primitive argument:** The method receives a copy of the primitive value.
- **Object argument:** The method receives a copy of the reference value. Both references can point to the same object.

```java
static void update(Student s) {
    s.name = "Ravi";       // Mutates the shared object
    s = new Student();     // Reassigns only the local parameter
}
```

Changes made to the shared object's mutable state may be visible to the caller. Reassigning the parameter does not change the caller's reference variable.

## Reference Aliasing
```java
Student a = new Student();
Student b = a;
```

Both variables refer to the same object. Mutating that object through either reference is visible through the other.

## Shallow vs. Deep Copy
- **Shallow copy:** Creates a new outer object but shares references to nested objects.
- **Deep copy:** Copies nested objects as well, to the intended depth, so mutable state can be independent.

A simple assignment such as `b = a` creates no copy of the object—it copies the reference.

Java does not automatically deep-copy arbitrary objects. Copy behavior depends on the implementation.

## Key Points
- Java is not call-by-reference.
- Reassigning a method parameter does not reassign the caller's variable.
- Shallow copies may share mutable nested state.
- Deep-copy implementations must account for nested references and object relationships.
