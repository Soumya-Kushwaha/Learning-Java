# Abstraction, Abstract Classes & Interfaces

## Abstraction
Exposes **what an object can do** while hiding unnecessary implementation details.

- Simplifies usage by presenting a clear contract.
- **Encapsulation** controls access to internal state; **abstraction** focuses on essential behavior and hides implementation complexity.

## Abstract Classes
- Declared using `abstract`.
- Cannot be instantiated directly.
- Can contain abstract methods, concrete methods, constructors, and fields.
- A concrete subclass must implement inherited abstract methods unless it is also abstract.

```java
abstract class Shape {
    abstract double area();

    void describe() {
        System.out.println("A shape");
    }
}

class Circle extends Shape {
    private final double radius;

    Circle(double radius) {
        this.radius = radius;
    }

    @Override
    double area() {
        return Math.PI * radius * radius;
    }
}
```

## Interfaces
- Define a contract that implementing classes agree to support.
- A class can implement multiple interfaces.
- Interfaces can declare abstract methods, `default` and `static` methods, and constants (`public static final` fields).
- Modern Java interfaces can also contain private helper methods.
- Interfaces cannot be instantiated directly and do not have constructors.

```java
interface Printable {
    void print();
}

class Report implements Printable {
    @Override
    public void print() {
        System.out.println("Printing report");
    }
}
```

Interface implementation methods must be `public` when implementing public interface methods.

## Abstract Class vs. Interface

| Abstract class | Interface |
|---|---|
| Extended with `extends` | Implemented with `implements` |
| A class can extend only one class | A class can implement multiple interfaces |
| Can hold instance state | Fields are implicitly `public static final` |
| Can define constructors | Cannot declare constructors |
| Useful for shared base state and behavior | Useful for contracts and capabilities |

## Choosing Between Them
- Use an **abstract class** when related classes need shared state or common implementation.
- Use an **interface** to define a capability or contract that potentially unrelated classes can implement.
