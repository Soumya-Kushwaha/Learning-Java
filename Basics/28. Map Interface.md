# Map Interface & Implementations

## 1. Map Interface

`Map<K, V>` represents a collection of **key-value pairs**.

- Each key is unique.
- Multiple keys can map to equal values.
- A key maps to at most one value at a time.
- Adding an existing key replaces its previous value.
- `Map` does not extend `Collection`.

```java
Map<Integer, String> students = new HashMap<>();

students.put(101, "Asha");
students.put(102, "Ravi");
students.put(101, "Maya");

System.out.println(students);
// {101=Maya, 102=Ravi}
```

The value associated with key `101` is replaced.

## 2. Map Hierarchy

```text
Map
 |
 +---------------------+
 |                     |
HashMap              SortedMap
 |                     |
LinkedHashMap       NavigableMap
                       |
                    TreeMap

Other Map implementations:
- Hashtable
- WeakHashMap
- IdentityHashMap
- EnumMap
- ConcurrentHashMap
```

This is a simplified view of commonly used implementations.

### Important interfaces

| Interface | Purpose |
|---|---|
| `Map<K,V>` | Stores key-value mappings |
| `SortedMap<K,V>` | Maintains keys in sorted order |
| `NavigableMap<K,V>` | Extends `SortedMap` with navigation operations |

## 3. Core Map Methods

| Method | Purpose | Return value |
|---|---|---|
| `put(K key, V value)` | Adds or replaces a mapping | Previous value, or `null` |
| `get(Object key)` | Retrieves the value for a key | Value, or `null` |
| `size()` | Returns number of mappings | `int` |
| `isEmpty()` | Checks whether map is empty | `boolean` |
| `containsKey(Object key)` | Checks whether a key exists | `boolean` |
| `containsValue(Object value)` | Checks whether a value exists | `boolean` |
| `remove(Object key)` | Removes a mapping by key | Previous value, or `null` |
| `clear()` | Removes all mappings | `void` |

### 3.1 `put()`

Adds a new key-value mapping or replaces the value associated with an existing key.

```java
Map<Integer, String> students = new HashMap<>();

students.put(101, "Asha");
students.put(102, "Ravi");
students.put(101, "Maya");

System.out.println(students.get(101)); // Maya
```

### 3.2 `get()`

Returns the value associated with a key.

```java
System.out.println(students.get(102)); // Ravi
System.out.println(students.get(999)); // null
```

**Important:** A `null` result does not always mean the key is absent. The key may exist and explicitly map to `null`. Use `containsKey()` to distinguish these cases.

### 3.3 `containsKey()` and `containsValue()`

```java
System.out.println(students.containsKey(101)); // true
System.out.println(students.containsValue("Maya")); // true
```

In a typical `HashMap`:
- `containsKey()` has expected \(O(1)\) performance.
- `containsValue()` takes \(O(n)\), because values generally need to be scanned.

### 3.4 `remove()`

Removes the mapping associated with a key.

```java
students.remove(102);

System.out.println(students.containsKey(102)); // false
```

## 4. Key and Value Views

A `Map` provides three important views of its contents.

| Method | Returns | Purpose |
|---|---|---|
| `keySet()` | `Set<K>` | View of all keys |
| `values()` | `Collection<V>` | View of all values |
| `entrySet()` | `Set<Map.Entry<K,V>>` | View of key-value entries |

### 4.1 `keySet()`

```java
for (Integer key : students.keySet()) {
    System.out.println(key);
}
```

### 4.2 `values()`

```java
for (String value : students.values()) {
    System.out.println(value);
}
```

### 4.3 `entrySet()`

An entry represents one key-value mapping.

```java
for (Map.Entry<Integer, String> entry : students.entrySet()) {
    System.out.println(
        entry.getKey() + " = " + entry.getValue()
    );
}
```

`entrySet()` is often the preferred way to traverse both keys and values together.

**Important:** These are backed views, not independent copies. Changes to the map are reflected in the views, and supported view operations can affect the map.

## 5. Useful Map Methods

### 5.1 `getOrDefault()`

Returns the mapped value if the key exists; otherwise, returns the supplied default value.

```java
Map<Integer, String> students = new HashMap<>();
students.put(101, "Asha");

System.out.println(students.getOrDefault(101, "Unknown"));
// Asha

System.out.println(students.getOrDefault(102, "Unknown"));
// Unknown
```

### 5.2 `putIfAbsent()`

Adds a mapping only if the key is currently absent or mapped to `null`.

```java
Map<Integer, String> students = new HashMap<>();

students.put(101, "Asha");
students.putIfAbsent(101, "Maya");
students.putIfAbsent(102, "Ravi");

System.out.println(students);
// {101=Asha, 102=Ravi}
```

For a map that permits null values, an existing key mapped to `null` can receive the new value.

### 5.3 `replace()`

Replaces a value only if the key is already mapped.

```java
Map<Integer, String> students = new HashMap<>();

students.put(101, "Asha");

students.replace(101, "Maya");
students.replace(102, "Ravi"); // No effect

System.out.println(students); // {101=Maya}
```

There is also a conditional overload:

```java
students.replace(101, "Maya", "Neha");
```

This replaces the value only if the current value matches the supplied old value.

### 5.4 `remove(key, value)`

Removes the mapping only if both the key and its current value match.

```java
students.remove(101, "Neha");
```

### 5.5 `forEach()`

Applies an action to each key-value mapping.

```java
students.forEach((key, value) ->
    System.out.println(key + " = " + value)
);
```

## 6. HashMap

`HashMap<K,V>` is a hash-table-based implementation of `Map`.

### Characteristics

- Stores key-value pairs.
- Does not guarantee iteration order.
- Allows one `null` key.
- Allows multiple `null` values.
- Provides expected \(O(1)\) basic operations under suitable hashing conditions.
- Is not synchronized by default.

### Internal working

A `HashMap` uses an internal array of buckets.

When inserting a mapping:

1. Java obtains the key's hash code.
2. The hash is processed to determine a bucket index.
3. The key-value entry is stored in that bucket.
4. If another key maps to the same bucket, collision handling is required.
5. Keys are compared using `equals()` when necessary to identify an existing mapping.

```text
HashMap
+-------------------+
| Bucket 0          |
| Bucket 1 -> Entry A
|            -> Entry B
| Bucket 2          |
| Bucket 3 -> Entry C
+-------------------+
```

### Collision handling

Common JDK implementations use linked structures within buckets and can convert sufficiently long buckets into Red-Black Trees under certain conditions.

This improves performance when many entries collide in one bucket.

### Load factor and resizing

The default load factor is commonly `0.75`.

\[
\text{Threshold} = \text{Capacity} \times \text{Load Factor}
\]

When the threshold is exceeded, the table is resized. The capacity commonly doubles, and entries are redistributed into the new table.

These internal details describe common JDK implementations, not guarantees of the `Map` interface.

### Example

```java
Map<String, Integer> marks = new HashMap<>();

marks.put("Asha", 90);
marks.put("Ravi", 85);
marks.put("Maya", 95);

System.out.println(marks.get("Ravi")); // 85
```

### Constructors

```java
HashMap<String, Integer> map1 = new HashMap<>();

HashMap<String, Integer> map2 = new HashMap<>(32);

HashMap<String, Integer> map3 =
    new HashMap<>(32, 0.75f);

HashMap<String, Integer> map4 =
    new HashMap<>(anotherMap);
```

## 7. LinkedHashMap

`LinkedHashMap<K,V>` extends `HashMap` and maintains a defined encounter order.

By default, it maintains **insertion order**.

### Characteristics

- Maintains key-value mappings using hashing.
- Maintains insertion order using linked connections between entries.
- Allows one `null` key and multiple `null` values.
- Expected \(O(1)\) basic operations under suitable hashing conditions.
- Has additional memory overhead for ordering information.

```java
Map<Integer, String> students = new LinkedHashMap<>();

students.put(101, "Asha");
students.put(102, "Ravi");
students.put(103, "Maya");

System.out.println(students);
// {101=Asha, 102=Ravi, 103=Maya}
```

### Insertion-order vs access-order

`LinkedHashMap` can also be configured to maintain access order rather than insertion order.

This is useful for implementing cache-like structures such as least-recently-used (LRU) caches.

## 8. TreeMap

`TreeMap<K,V>` is a sorted implementation of `NavigableMap`.

It uses a self-balancing Red-Black Tree to maintain keys in sorted order.

### Characteristics

- Maintains keys in sorted order.
- Basic lookup, insertion, and deletion take \(O(\log n)\).
- Supports range queries and navigation.
- Uses natural key ordering or a supplied `Comparator`.
- Does not support null keys under natural ordering; a custom comparator may permit them.
- Can contain null values.

```java
Map<Integer, String> students = new TreeMap<>();

students.put(103, "Maya");
students.put(101, "Asha");
students.put(102, "Ravi");

System.out.println(students);
// {101=Asha, 102=Ravi, 103=Maya}
```

## 9. SortedMap and NavigableMap Methods

### SortedMap methods

| Method | Purpose |
|---|---|
| `firstKey()` | Returns the smallest key |
| `lastKey()` | Returns the largest key |
| `headMap(toKey)` | Returns a view of mappings with keys smaller than the endpoint |
| `tailMap(fromKey)` | Returns a view of mappings with keys greater than or equal to the starting point |
| `subMap(fromKey, toKey)` | Returns a view of mappings from the starting key (inclusive) to the endpoint (exclusive) |
| `comparator()` | Returns the comparator, or `null` for natural ordering |

### Example

```java
TreeMap<Integer, String> map = new TreeMap<>();

map.put(10, "A");
map.put(20, "B");
map.put(30, "C");
map.put(40, "D");

System.out.println(map.firstKey()); // 10
System.out.println(map.lastKey());  // 40

System.out.println(map.headMap(30)); // {10=A, 20=B}
System.out.println(map.tailMap(30)); // {30=C, 40=D}
System.out.println(map.subMap(20, 40)); // {20=B, 30=C}
```

These methods return backed views, not independent copies.

### NavigableMap methods

| Method | Purpose |
|---|---|
| `lowerKey(key)` | Greatest key strictly less than the given key |
| `floorKey(key)` | Greatest key less than or equal to the given key |
| `ceilingKey(key)` | Smallest key greater than or equal to the given key |
| `higherKey(key)` | Smallest key strictly greater than the given key |
| `firstEntry()` | Returns the first key-value entry |
| `lastEntry()` | Returns the last key-value entry |
| `pollFirstEntry()` | Retrieves and removes the first entry |
| `pollLastEntry()` | Retrieves and removes the last entry |
| `descendingMap()` | Returns a reverse-order view of the map |

## 10. Immutable Maps — `Map.of()`

Java 9 introduced factory methods such as `Map.of()` for creating unmodifiable maps.

```java
Map<Integer, String> students = Map.of(
    101, "Asha",
    102, "Ravi",
    103, "Maya"
);
```

Characteristics:
- The returned map is unmodifiable.
- Adding, removing, or replacing mappings throws `UnsupportedOperationException`.
- Null keys and null values are not permitted.
- Duplicate keys are rejected.

For more than ten key-value pairs, use `Map.ofEntries()`.

```java
Map<Integer, String> students = Map.ofEntries(
    Map.entry(101, "Asha"),
    Map.entry(102, "Ravi")
);
```

**Important:** `Map.of()` does not create a mutable `HashMap`.

## 11. Legacy and Specialized Map Implementations

### 11.1 Hashtable

`Hashtable<K,V>` is a legacy synchronized implementation of `Map`.

Characteristics:
- Synchronizes individual methods.
- Does not permit null keys or null values.
- Generally has more synchronization overhead than `HashMap` in single-threaded use.
- Is largely superseded by modern alternatives.

For concurrent access, `ConcurrentHashMap` is generally preferred over `Hashtable`.

### 11.2 ConcurrentHashMap

`ConcurrentHashMap<K,V>` is designed for concurrent access by multiple threads.

Characteristics:
- Supports concurrent retrievals and updates.
- Does not permit null keys or null values.
- Provides better concurrency characteristics than synchronizing an entire map for every operation.
- Is not a replacement for every atomic multi-operation workflow; use its atomic methods when required.

```java
Map<String, Integer> counts = new ConcurrentHashMap<>();

counts.put("Java", 1);
counts.merge("Java", 1, Integer::sum);

System.out.println(counts.get("Java")); // 2
```

### 11.3 Properties

`Properties` is a legacy class used for configuration and property data.

It extends `Hashtable<Object,Object>` and is commonly used with string keys and values.

```java
Properties properties = new Properties();

properties.setProperty("app.name", "MyApplication");
properties.setProperty("app.version", "1.0");

System.out.println(properties.getProperty("app.name"));
```

It supports loading and storing property data from streams and readers.

### 11.4 WeakHashMap

`WeakHashMap<K,V>` stores keys using weak references.

If a key is no longer strongly reachable elsewhere, it can become eligible for garbage collection, and its mapping may subsequently disappear.

This behavior makes `WeakHashMap` useful for certain cache-like or metadata associations where keys should not be kept alive solely by the map.

**Important:** Garbage collection timing is not deterministic. Do not treat `WeakHashMap` as a predictable eviction-policy cache.

### 11.5 IdentityHashMap

`IdentityHashMap<K,V>` compares keys using reference identity (`==`) instead of logical equality (`equals()`).

A regular `HashMap` uses `equals()` and `hashCode()` for key matching.

```java
String first = new String("Java");
String second = new String("Java");

Map<String, Integer> hashMap = new HashMap<>();
hashMap.put(first, 1);
hashMap.put(second, 2);

System.out.println(hashMap.size()); // 1

Map<String, Integer> identityMap = new IdentityHashMap<>();
identityMap.put(first, 1);
identityMap.put(second, 2);

System.out.println(identityMap.size()); // 2
```

The two strings have equal contents but are different objects.

**Use case:** Specialized situations where object identity matters more than logical equality, such as object graph processing.

### 11.6 EnumMap

`EnumMap<K extends Enum<K>, V>` is a specialized map for enum keys.

Characteristics:
- Keys must belong to one enum type.
- Maintains keys in enum declaration order.
- Uses an efficient array-based internal representation.
- Generally provides very efficient operations.
- Does not permit null keys, but permits null values.

```java
enum Day {
    MONDAY, TUESDAY, WEDNESDAY
}

Map<Day, String> schedule = new EnumMap<>(Day.class);

schedule.put(Day.MONDAY, "Java");
schedule.put(Day.TUESDAY, "Spring");
schedule.put(Day.WEDNESDAY, "SQL");

System.out.println(schedule);
```

Because enum constants have fixed ordinals, `EnumMap` can use an array-oriented representation rather than general-purpose hashing.

## 12. HashMap vs LinkedHashMap vs TreeMap

| Feature | HashMap | LinkedHashMap | TreeMap |
|---|---|---|---|
| Internal structure | Hash table | Hash table + linked ordering | Red-Black Tree |
| Key order | No guarantee | Insertion order by default | Sorted order |
| Basic operations | Expected \(O(1)\) | Expected \(O(1)\) | \(O(\log n)\) |
| Null keys | One allowed | One allowed | Natural ordering rejects null |
| Null values | Allowed | Allowed | Allowed |
| Best suited for | Fast key-value lookup | Lookup with predictable iteration order | Sorted keys and range queries |

## 13. HashMap vs Hashtable vs ConcurrentHashMap

| Feature | HashMap | Hashtable | ConcurrentHashMap |
|---|---|---|---|
| Thread safety | Not synchronized | Synchronized methods | Designed for concurrent access |
| Null keys | One allowed | Not allowed | Not allowed |
| Null values | Allowed | Not allowed | Not allowed |
| Status | Modern general-purpose choice | Legacy | Modern concurrent choice |

9. **What is the difference between `keySet()` and `values()`?** One exposes keys; the other exposes values.
10. **What is `getOrDefault()`?** Retrieves a mapping or returns a supplied fallback when the key is absent.
11. **What does `putIfAbsent()` do?** Inserts a value when the key is absent or currently mapped to null.
12. **What is `Map.of()`?** A Java 9 factory method for creating an unmodifiable map.
13. **What is the difference between HashMap and IdentityHashMap?** Logical equality versus reference identity for keys.
14. **What is WeakHashMap?** A map with weakly referenced keys.
15. **What is EnumMap?** An efficient map specialized for enum keys.
16. **Why use ConcurrentHashMap?** For map access and updates from multiple threads without synchronizing the entire map for every operation.
17. **What is Hashtable?** A legacy synchronized map implementation that disallows null keys and values.
