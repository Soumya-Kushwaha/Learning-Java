# Collection Interface

## 1. Overview

`Collection<E>` is the root interface for groups of elements in the Java Collections Framework. It defines common operations shared by collections such as `List`, `Set`, and `Queue`.

It enables **polymorphism**: code can work with the `Collection` interface without depending on a specific implementation such as `ArrayList` or `HashSet`.

```java
Collection<String> items = new ArrayList<>();
items.add("Java");
items.add("Spring");

System.out.println(items.size()); // 2
```

The implementation can be changed to another suitable collection without changing code that uses only the `Collection` contract.

**Important:** `Map` belongs to the Java Collections Framework but does not extend `Collection`, because it represents key-value mappings.

## 2. `Collection` vs `Collections`

| `Collection` | `Collections` |
|---|---|
| An interface | A utility class in `java.util` |
| Represents a group of elements | Provides static utility methods for working with collections |
| Declares operations such as `add()`, `remove()`, and `size()` | Provides methods such as `sort()`, `reverse()`, `shuffle()`, and `binarySearch()` |

```java
Collection<Integer> numbers = new ArrayList<>();
numbers.add(30);
numbers.add(10);
numbers.add(20);

Collections.sort((List<Integer>) numbers);
```

Here, `Collections.sort()` requires a `List`, not an arbitrary `Collection`. A clearer version is to declare the variable as `List<Integer>` when list-specific operations are needed.

```java
List<Integer> numbers = new ArrayList<>();
numbers.add(30);
numbers.add(10);
numbers.add(20);

Collections.sort(numbers);
```

## 3. Core Methods

The following methods are declared by `Collection` or inherited through its parent interfaces. Exact performance and behavior depend on the implementation.

| Method | Purpose | Return value |
|---|---|---|
| `size()` | Returns the number of elements | `int` |
| `isEmpty()` | Checks whether the collection contains no elements | `boolean` |
| `contains(Object o)` | Checks whether an equal element exists | `boolean` |
| `add(E e)` | Attempts to add an element | `boolean` |
| `remove(Object o)` | Removes one matching element, if present | `boolean` |
| `clear()` | Removes all elements | `void` |
| `iterator()` | Returns an iterator for traversal | `Iterator<E>` |

### 3.1 `size()` and `isEmpty()`

```java
Collection<String> names = new ArrayList<>();

System.out.println(names.size());    // 0
System.out.println(names.isEmpty()); // true

names.add("Asha");

System.out.println(names.size());    // 1
System.out.println(names.isEmpty()); // false
```

Use `isEmpty()` when the question is simply whether a collection contains any elements.

### 3.2 `contains(Object o)`

Checks whether the collection contains an element equal to the supplied object. For ordinary objects, this generally relies on `equals()` rather than reference identity.

```java
List<String> names = new ArrayList<>();
names.add("Java");

System.out.println(names.contains("Java")); // true
System.out.println(names.contains("Python")); // false
```

Performance depends on the implementation:
- `ArrayList`: typically \(O(n)\).
- `HashSet`: expected \(O(1)\) with suitable hashing.
- `TreeSet`: typically \(O(\log n)\).

### 3.3 `add(E e)`

Attempts to add an element to the collection.

```java
Collection<Integer> numbers = new ArrayList<>();

System.out.println(numbers.add(10)); // true
System.out.println(numbers.add(20)); // true
```

The returned boolean indicates whether the collection changed as a result of the operation.

A `List` normally accepts duplicates, whereas a `Set` rejects an element that is already present according to its equality rules.

```java
Set<Integer> numbers = new HashSet<>();

System.out.println(numbers.add(10)); // true
System.out.println(numbers.add(10)); // false
```

Some implementations may reject certain elements or operations, for example with `UnsupportedOperationException` or `NullPointerException`, depending on their contract.

### 3.4 `remove(Object o)`

Removes one matching occurrence of the specified object, if present.

```java
List<Integer> numbers = new ArrayList<>(
    Arrays.asList(10, 20, 10, 30)
);

numbers.remove(Integer.valueOf(10));

System.out.println(numbers); // [20, 10, 30]
```

**Overload gotcha:** `List` has both `remove(int index)` and the inherited `remove(Object o)` method. Passing an `int` selects the index-based overload.

```java
numbers.remove(0);                    // Removes the element at index 0
numbers.remove(Integer.valueOf(10));  // Removes a matching value
```

### 3.5 `clear()`

Removes all elements from the collection.

```java
Collection<String> items = new ArrayList<>(
    Arrays.asList("Java", "Spring")
);

items.clear();

System.out.println(items.isEmpty()); // true
```

`clear()` does not delete the collection object itself; it removes its elements.

## 4. Bulk Operations

Bulk operations work with another collection or with multiple elements at once.

| Method | Purpose |
|---|---|
| `addAll(Collection<? extends E> c)` | Adds all elements from another collection |
| `containsAll(Collection<?> c)` | Checks whether all supplied elements are present |
| `removeAll(Collection<?> c)` | Removes elements that match elements in the supplied collection |
| `retainAll(Collection<?> c)` | Keeps only elements that match elements in the supplied collection |

### 4.1 `addAll()`

```java
List<Integer> numbers = new ArrayList<>();
numbers.add(10);

numbers.addAll(Arrays.asList(20, 30));

System.out.println(numbers); // [10, 20, 30]
```

Returns `true` if the collection changed.

### 4.2 `containsAll()`

```java
List<Integer> numbers = Arrays.asList(10, 20, 30);

System.out.println(
    numbers.containsAll(Arrays.asList(10, 30))
); // true
```

Returns `true` if every element in the supplied collection is present. Duplicate counts are not checked as a multiset; membership is checked for each supplied element.

### 4.3 `removeAll()`

Removes elements that are also represented in the supplied collection.

```java
List<Integer> numbers = new ArrayList<>(
    Arrays.asList(10, 20, 30, 40)
);

numbers.removeAll(Arrays.asList(20, 40));

System.out.println(numbers); // [10, 30]
```

Returns `true` if the collection changed.

### 4.4 `retainAll()`

Keeps only elements that are also represented in the supplied collection.

```java
List<Integer> numbers = new ArrayList<>(
    Arrays.asList(10, 20, 30, 40)
);

numbers.retainAll(Arrays.asList(20, 40, 50));

System.out.println(numbers); // [20, 40]
```

Returns `true` if the collection changed.

**Important:** Bulk operations may be unsupported by unmodifiable collections. Their performance depends on the implementations involved.

## 5. Converting a Collection to an Array

The `Collection` interface provides two `toArray()` overloads.

### 5.1 `toArray()`

Returns an array of `Object`.

```java
List<String> names = Arrays.asList("Asha", "Ravi");

Object[] array = names.toArray();

System.out.println(array[0]); // Asha
```

Because the result is an `Object[]`, it cannot be assigned directly to a `String[]`.

### 5.2 `toArray(T[] a)`

Returns an array of the requested component type.

```java
List<String> names = Arrays.asList("Asha", "Ravi");

String[] array = names.toArray(new String[0]);

System.out.println(array[0]); // Asha
```

If the supplied array is large enough, it is filled and reused; if it is too small, a new array of the same runtime component type is allocated.

If the supplied array has extra capacity, the element immediately after the collection's contents is set to `null`.

### 5.3 `toArray(IntFunction<T[]> generator)`

Java 11 added a convenient overload that accepts an array generator.

```java
List<String> names = Arrays.asList("Asha", "Ravi");

String[] array = names.toArray(String[]::new);
```

This avoids explicitly passing an empty array and lets the collection request an array of the required size.

**Interview point:** `toArray()` returns `Object[]`; use a typed overload when a specific array type is required.

## 6. Modern Methods on `Collection`

Modern Java includes default methods that make common collection operations more convenient.

### 6.1 `removeIf(Predicate<? super E> filter)`

Removes elements that satisfy the given predicate.

```java
List<Integer> numbers = new ArrayList<>(
    Arrays.asList(10, 15, 20, 25, 30)
);

numbers.removeIf(number -> number % 2 != 0);

System.out.println(numbers); // [10, 20, 30]
```

The predicate is a function that returns `true` for elements to remove. This method is useful with lambdas.

### 6.2 `stream()`

Creates a sequential stream for processing the collection's elements.

```java
List<Integer> numbers = Arrays.asList(10, 20, 30);

numbers.stream()
       .filter(number -> number > 10)
       .forEach(System.out::println);
```

Output:

```text
20
30
```

### 6.3 `parallelStream()`

Creates a stream that is intended for parallel processing.

```java
numbers.parallelStream()
       .filter(number -> number > 10)
       .forEach(System.out::println);
```

Parallel execution does not guarantee output order for operations such as `forEach()`. It is not automatically faster; performance depends on the workload, data size, and execution environment.

**Note:** `stream()` and `parallelStream()` return streams; they do not directly modify the collection.

## 7. Polymorphism with `Collection`

Programming against the interface allows methods to accept different collection implementations.

```java
static void printElements(Collection<String> items) {
    for (String item : items) {
        System.out.println(item);
    }
}
```

The method can accept an `ArrayList`, `LinkedList`, or `HashSet` because each implements `Collection<String>`.

However, only use operations guaranteed by the declared interface. If code needs list-specific behavior such as indexed access, declare or accept a `List` instead.

## 8. Interview Quick Revision

1. **What is `Collection`?** The root interface for groups of elements in the Java Collections Framework.
2. **Does `Map` extend `Collection`?** No; it represents key-value mappings.
3. **`Collection` vs `Collections`?** Interface versus utility class.
4. **What does `contains()` use for ordinary objects?** Equality, typically through `equals()`.
5. **What does `add()` return?** Whether the collection changed.
6. **What is the difference between `removeAll()` and `retainAll()`?** The former removes matching elements; the latter keeps matching elements.
7. **What does `toArray()` return?** An `Object[]`.
8. **How do you obtain a typed array?** Use `toArray(T[] a)` or the generator overload.
9. **What does `removeIf()` do?** Removes elements matching a predicate.
10. **What is the difference between `stream()` and `parallelStream()`?** Sequential versus parallel stream execution mode by default; parallelism is not a guarantee of better performance.
11. **Why use `Collection` as a parameter type?** It allows polymorphic use of different collection implementations when only common collection operations are required.
