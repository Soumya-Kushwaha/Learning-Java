# Object Class & Its Methods

`java.lang.Object` is the root superclass of Java classes. A class without an explicit superclass implicitly extends `Object` (except `Object` itself). Arrays also support its methods.

## 1. `toString()`

Returns a string representation of an object.

```java
class Employee {
    String name;

    @Override
    public String toString() {
        return "Employee{name='" + name + "'}";
    }
}
```

- Default format is typically `ClassName@hexHashCode`; it is not guaranteed to be a memory address.
- Override it to provide useful debugging or readable output.
- String concatenation with an object generally invokes its `toString()` method.

## 2. `equals()`

Compares objects for logical equality.

- Default `Object.equals()` compares reference identity, like `==`.
- Override it when equality should depend on field values.
- Follow the equality contract:
  - **Reflexive:** `x.equals(x)` is `true`.
  - **Symmetric:** `x.equals(y)` equals `y.equals(x)`.
  - **Transitive:** if `x.equals(y)` and `y.equals(z)`, then `x.equals(z)`.
  - **Consistent:** repeated calls return the same result while relevant state is unchanged.
  - **Non-null:** `x.equals(null)` is `false`.

```java
@Override
public boolean equals(Object obj) {
    if (this == obj) return true;
    if (!(obj instanceof Employee other)) return false;
    return java.util.Objects.equals(name, other.name);
}
```

This example uses modern Java pattern matching for `instanceof`. For older Java versions, use an explicit cast after the type check.

## 3. `hashCode()`

Returns an integer hash value used by hash-based collections.

**Contract:** if `a.equals(b)` is `true`, then `a.hashCode() == b.hashCode()` must also be `true`. Unequal objects may have the same hash code.

```java
@Override
public int hashCode() {
    return java.util.Objects.hash(name);
}
```

- Whenever you override `equals()`, normally override `hashCode()` too.
- `HashMap` and `HashSet` use hash codes to locate candidate entries, then use equality to distinguish keys or elements.
- Changing fields used by `equals()`/`hashCode()` while an object is a hash-map key can make it difficult to find in the map.

## 4. `getClass()` and `instanceof`

```java
obj.getClass();          // Runtime Class object
obj instanceof Employee; // true if compatible with Employee
```

- `getClass()` returns the object's actual runtime class; it cannot be overridden.
- `instanceof` checks type compatibility:
-   - exact class specified
    - subclasses
    - implemented interfaces.
- `null instanceof Employee` evaluates to `false`; calling `getClass()` on `null` throws `NullPointerException`.

## 5. `clone()` and `Cloneable`

`Object.clone()` creates a **shallow copy**: fields are copied, but referenced objects are not recursively duplicated.

- The class generally must implement the marker interface `Cloneable`; otherwise, `clone()` throws `CloneNotSupportedException`.
- `Cloneable` does not declare a `clone()` method; it signals permission for `Object.clone()`.
- The default `clone()` is `protected`, so it is not directly callable on arbitrary objects from unrelated code.
- Cloning is often avoided in favor of copy constructors, factory methods, or explicit copy methods.

## 6. `finalize()`

- Deprecated for removal because its execution is unpredictable and it can cause reliability and security problems.
- Do not use it for resource cleanup.
- Prefer `try`-with-resources for resources implementing `AutoCloseable`.

## 7. `wait()`, `notify()`, `notifyAll()`

Methods used for coordination between threads through an object's monitor.

- Must be called while holding that same object's monitor, usually inside a `synchronized` block or method; otherwise, `IllegalMonitorStateException` is thrown.
- `wait()` releases the monitor and suspends the thread until notified, interrupted, or timed out.
- `notify()` wakes one waiting thread; `notifyAll()` wakes all waiting threads. Awakened threads must reacquire the monitor.
- Always check the waiting condition in a loop because a thread can wake up without the condition being satisfied.

```java
synchronized (lock) {
    while (!condition) {
        lock.wait();
    }
    // Proceed when the condition is satisfied.
}
```

## Interview Quick Revision

- `==` compares primitive values or reference identity; `equals()` can compare logical equality.
- Equal objects **must** have equal hash codes; equal hash codes do not guarantee equal objects.
- `toString()` improves object readability; it does not define equality.
- `Object.clone()` performs a shallow copy by default.
- `finalize()` is deprecated; use explicit resource management.
- `wait()` releases the monitor; `sleep()` does not release a monitor held by the sleeping thread.
