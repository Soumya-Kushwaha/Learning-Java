# Iterable, Iterator & For-Each Loop

## 1. The Problem of Iteration

Different data structures store and organize elements differently. Their traversal methods can therefore differ.

For example:
- `ArrayList` supports index-based access.
- `LinkedList` stores elements in linked nodes.
- `HashSet` does not provide index-based access.

If code depends on each implementation's internal structure, it becomes tightly coupled to that implementation. Replacing one data structure with another may require rewriting the traversal logic.

**Solution:** Java provides the `Iterable` and `Iterator` interfaces to standardize traversal.

## 2. The `Iterable` Interface

`Iterable<E>` is an interface in `java.lang`. It represents an object whose elements can be traversed and provides an `iterator()` method that returns an `Iterator<E>`.

The `Collection<E>` interface extends `Iterable<E>`, so standard collection implementations inherit this traversal capability.

```java
public interface Iterable<T> {
    Iterator<T> iterator();
    // Other default methods are omitted
}
```

The code above is a simplified illustration, not the complete interface declaration.

### Why is `Iterable` useful?

- Provides a common way to traverse elements.
- Reduces dependence on a collection's internal implementation.
- Enables the enhanced `for-each` loop.
- Allows traversal logic to be separated from storage logic.

## 3. The `Iterator` Interface

An `Iterator<E>` is an object that traverses elements one at a time.

Its two primary methods are:

| Method | Purpose |
|---|---|
| `hasNext()` | Returns `true` if another element is available |
| `next()` | Returns the next element and advances the iterator |

The `Iterator` interface also defines `remove()`, an optional operation that removes the last element returned by `next()`. Some iterators do not support removal and may throw `UnsupportedOperationException`.

### Example: Manual iteration

```java
import java.util.ArrayList;
import java.util.Iterator;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<String> names = new ArrayList<>();
        names.add("Asha");
        names.add("Ravi");
        names.add("Maya");

        Iterator<String> iterator = names.iterator();

        while (iterator.hasNext()) {
            String name = iterator.next();
            System.out.println(name);
        }
    }
}
```

**Output:**

```text
Asha
Ravi
Maya
```

### How does it work?

1. `names.iterator()` obtains an iterator for the list.
2. `hasNext()` checks whether another element is available.
3. `next()` returns the next element and advances the iterator.
4. The loop ends when `hasNext()` returns `false`.

**Important:** Calling `next()` when no elements remain normally throws `NoSuchElementException`. Check `hasNext()` before calling `next()` when traversing manually.

## 4. The Enhanced `for-each` Loop

Java's enhanced `for` loop provides concise syntax for traversing arrays and objects that implement `Iterable`.

```java
for (String name : names) {
    System.out.println(name);
}
```

For an `Iterable` object, the enhanced `for` loop uses its iterator behind the scenes. Conceptually, the code is equivalent to:

```java
for (Iterator<String> it = names.iterator(); it.hasNext(); ) {
    String name = it.next();
    System.out.println(name);
}
```

The compiler translates the enhanced loop into iterator-based traversal for `Iterable` objects. Arrays are handled differently: the loop uses array indexing rather than the `Iterable` interface.

### Advantages

- Less boilerplate than manually creating an iterator.
- Works across different collection implementations.
- Makes traversal code easier to read.
- Does not require the caller to know how elements are stored internally.

### Limitation

The enhanced `for-each` loop does not directly expose the iterator, so you cannot call `iterator.remove()` through the loop variable. If you need iterator-controlled removal, use an explicit iterator.

## 5. Separation of Storage and Traversal

The collection and its iterator have different responsibilities:

- **Collection:** Stores and manages elements.
- **Iterator:** Tracks traversal progress and retrieves elements.

This separation means the same traversal pattern can work with different collection implementations.

For example:

```java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        List<Integer> numbers = new ArrayList<>(
            Arrays.asList(10, 20, 30)
        );

        Set<Integer> uniqueNumbers = new HashSet<>(
            Arrays.asList(10, 20, 30)
        );

        printElements(numbers);
        printElements(uniqueNumbers);
    }

    static void printElements(Iterable<Integer> items) {
        for (Integer item : items) {
            System.out.println(item);
        }
    }
}
```

The `printElements` method accepts `Iterable<Integer>`, so it can traverse either collection without needing to know its concrete type.

**Note:** A `HashSet` does not guarantee the iteration order shown in the list example.

## 6. Multiple Iterators

Each call to `iterator()` normally creates a separate iterator with its own traversal state.

```java
List<Integer> numbers = Arrays.asList(10, 20, 30);

Iterator<Integer> first = numbers.iterator();
Iterator<Integer> second = numbers.iterator();

System.out.println(first.next());  // 10
System.out.println(first.next());  // 20

System.out.println(second.next()); // 10
```

Advancing `first` does not advance `second`.

This allows multiple traversals of the same collection to proceed independently. However, modifying a collection while multiple iterators are active may affect their behavior, depending on the collection and iterator contract.

## 7. Fail-Fast Iterators

Many standard collection implementations provide **fail-fast iterators**. If the collection is structurally modified outside the iterator while iteration is in progress, the iterator may detect the modification and throw `ConcurrentModificationException`.

A structural modification generally means adding or removing elements, rather than merely replacing an existing value.

Example:

```java
List<Integer> numbers = new ArrayList<>(
    Arrays.asList(10, 20, 30)
);

Iterator<Integer> iterator = numbers.iterator();

while (iterator.hasNext()) {
    Integer number = iterator.next();

    if (number == 20) {
        numbers.remove(number); // May throw ConcurrentModificationException
    }
}
```

The direct removal changes the list outside the iterator, potentially invalidating the iterator's expected modification state.

### Correct removal with an iterator

When supported, use `iterator.remove()`:

```java
Iterator<Integer> iterator = numbers.iterator();

while (iterator.hasNext()) {
    Integer number = iterator.next();

    if (number == 20) {
        iterator.remove();
    }
}
```

`iterator.remove()` removes the last element returned by `next()`, provided the operation is supported and the iterator's state permits it.

For a collection that supports it, another option is `removeIf()`:

```java
numbers.removeIf(number -> number == 20);
```

### Important fail-fast caveats

- Fail-fast behavior is **best-effort**, not a synchronization guarantee.
- Do not rely on `ConcurrentModificationException` to detect every modification.
- Fail-fast does not mean the collection is thread-safe.
- Some collections, such as `CopyOnWriteArrayList`, use different iterator behavior and do not follow the usual fail-fast model.

## 8. `Iterable` vs `Iterator`

| Feature | `Iterable` | `Iterator` |
|---|---|---|
| Purpose | Represents something that can be iterated over | Performs the traversal |
| Main method | `iterator()` | `hasNext()`, `next()` |
| Package | `java.lang` | `java.util` |
| Typical use | Enables enhanced `for-each` for objects | Manual element-by-element traversal |
| State | Does not represent a particular traversal's progress | Tracks progress through a traversal |

**Remember:** `Iterable` provides an iterator; `Iterator` moves through the elements.

## 9. Interview Quick Revision

1. **Why do we need `Iterable`?** To provide a standard way to obtain an iterator and support enhanced `for-each` traversal.
2. **What does `iterator()` return?** An `Iterator` for traversing the elements.
3. **What is the difference between `hasNext()` and `next()`?** `hasNext()` checks availability; `next()` retrieves and advances.
4. **What happens if `next()` is called after iteration ends?** It normally throws `NoSuchElementException`.
5. **How does the enhanced `for-each` loop work for collections?** It uses iterator-based traversal internally.
6. **Can arrays use enhanced `for-each`?** Yes, but arrays are traversed through array-specific compiler-generated logic, not `Iterable`.
7. **Can two iterators traverse the same collection independently?** Normally, yes; each iterator maintains its own traversal state.
8. **Why can modifying a collection during iteration cause `ConcurrentModificationException`?** A fail-fast iterator may detect structural modification made outside the iterator.
9. **How can you safely remove an element during iterator traversal?** Use `Iterator.remove()` when supported, or use a suitable collection operation such as `removeIf()`.
10. **Does fail-fast behavior guarantee thread safety?** No.
