# Set Interface & Hashing

## 1. Set Interface

`Set<E>` is an interface in the Java Collections Framework that represents a collection of **unique elements**.

- Does not allow duplicate elements.
- Does not provide index-based access.
- The iteration order depends on the implementation.
- Common implementations include `HashSet`, `LinkedHashSet`, and `TreeSet`.

```java
Set<Integer> numbers = new HashSet<>();

numbers.add(10);
numbers.add(20);
numbers.add(10); // Duplicate is not added

System.out.println(numbers.size()); // 2
```

A set determines duplicates using its equality rules. For hash-based sets, correct `equals()` and `hashCode()` implementations are important.

## 2. Set Hierarchy

```text
Iterable
   |
Collection
   |
  Set
   |
   +------------------+
   |                  |
HashSet            SortedSet
   |                  |
LinkedHashSet    NavigableSet
                      |
                   TreeSet
```

This is a simplified hierarchy. `LinkedHashSet` extends `HashSet`, while `TreeSet` implements `NavigableSet`.

### Important interfaces

| Interface | Purpose |
|---|---|
| `Set<E>` | Stores unique elements |
| `SortedSet<E>` | Maintains elements in sorted order |
| `NavigableSet<E>` | Extends `SortedSet` with navigation operations |

## 3. How Hashing Works

Hashing is a technique used to map an object to an integer hash value, which helps determine where the object should be stored or searched for.

Hash-based collections such as `HashSet` and `HashMap` use an internal array of **buckets**.

### Insertion process

1. An element is added.
2. Java obtains its hash code using `hashCode()`.
3. The hash is processed to determine a bucket index.
4. The element is stored in that bucket.
5. If another element maps to the same bucket, collision handling is required.

Conceptually:

```text
          Hash Table
       +-------------+
Index  |   Bucket    |
       +-------------+
  0    |             |
  1    |   Element A |
       |      |
       |   Element B |
  2    |             |
  3    |   Element C |
  4    |             |
       +-------------+
```

The diagram illustrates multiple elements occupying the same bucket due to a hash collision.

### `hashCode()` and `equals()`

These two methods work together in hash-based collections.

- `hashCode()` helps determine the bucket.
- `equals()` checks whether two objects are logically equal.

The contract requires:

1. If two objects are equal according to `equals()`, they must have the same hash code.
2. Two objects with the same hash code are not necessarily equal.
3. `equals()` and `hashCode()` should remain consistent while an object is used as a hash-based collection element or key.

Example:

```java
class Employee {
    int id;

    Employee(int id) {
        this.id = id;
    }

    @Override
    public int hashCode() {
        return Integer.hashCode(id);
    }

    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;

        if (!(obj instanceof Employee)) return false;

        Employee other = (Employee) obj;
        return this.id == other.id;
    }
}
```

```java
Set<Employee> employees = new HashSet<>();

employees.add(new Employee(101));
employees.add(new Employee(101));

System.out.println(employees.size()); // 1
```

Both objects have the same logical identity based on `id`, so the set retains only one.

**Important:** If you override `equals()`, you should also override `hashCode()` consistently.

## 4. Hash Collision and Chaining

A **hash collision** occurs when two different elements map to the same bucket.

Java's hash-based collections handle collisions using a bucket structure.

In common `HashMap` implementations:
- Multiple entries can occupy the same bucket.
- A linked structure is used for collision handling.
- Under certain conditions, a long bucket chain can be converted into a Red-Black Tree to improve lookup performance.

Conceptually:

```text
Bucket 2
   |
   v
[Element A] -> [Element B] -> [Element C]
```

When treeification occurs:

```text
          Element B
          /       \
    Element A   Element C
```

Treeification is an implementation optimization, not a guarantee that every collision chain becomes a tree.

## 5. Load Factor and Rehashing

The **load factor** determines how full a hash table is allowed to become before resizing is triggered.

\[
\text{Load Factor} =
\frac{\text{Number of entries}}{\text{Capacity}}
\]

For `HashMap` and the standard `HashSet` implementation:

- Default initial capacity is commonly 16.
- Default load factor is 0.75.
- When the size exceeds the threshold (`capacity × load factor`), resizing is triggered.
- The table capacity commonly doubles during resizing.

Example:

```text
Initial capacity = 16
Load factor      = 0.75
Threshold        = 16 × 0.75 = 12

When size exceeds 12:
Resize is triggered.
New capacity is commonly 32.
```

### What is rehashing?

When the hash table resizes, entries are redistributed into the new bucket array based on the new capacity.

This helps maintain efficient lookup and insertion as the collection grows.

**Note:** These capacity and resizing details describe common JDK implementations. They are not all guaranteed by the `Set` or `Map` interfaces.

## 6. HashSet

`HashSet<E>` is a hash-table-based implementation of `Set`.

### Characteristics

- Stores unique elements.
- Does not guarantee insertion order or sorted order.
- Allows one `null` element.
- Provides expected \(O(1)\) insertion, deletion, and lookup under suitable hashing conditions.
- Internally uses a `HashMap`.

### Internal implementation

A `HashSet` uses its elements as keys in an internal `HashMap`. The values are references to a shared dummy object called `PRESENT`.

Conceptually:

```java
map.put(element, PRESENT);
```

The actual implementation uses an internal map and a shared placeholder value.

### Example

```java
Set<String> languages = new HashSet<>();

languages.add("Java");
languages.add("Python");
languages.add("Java");

System.out.println(languages.size()); // 2
System.out.println(languages.contains("Java")); // true
```

### Constructors

```java
HashSet<String> set1 = new HashSet<>();

HashSet<String> set2 = new HashSet<>(32);

HashSet<String> set3 = new HashSet<>(32, 0.75f);

HashSet<String> set4 = new HashSet<>(
    Arrays.asList("Java", "Python")
);
```

| Constructor | Purpose |
|---|---|
| `HashSet()` | Creates an empty set with default capacity and load factor |
| `HashSet(int initialCapacity)` | Specifies initial capacity |
| `HashSet(int initialCapacity, float loadFactor)` | Specifies capacity and load factor |
| `HashSet(Collection<? extends E> c)` | Initializes the set using another collection |

## 7. LinkedHashSet

`LinkedHashSet<E>` extends `HashSet` and maintains insertion order.

### Characteristics

- Does not allow duplicates.
- Maintains insertion order during iteration.
- Uses hashing for membership operations.
- Maintains additional linked-list connections between entries.
- Allows one `null` element.

### Internal structure

It combines hash-table-based storage with linked ordering information.

```text
Insertion order:

[Java] <-> [Python] <-> [Spring] <-> [SQL]
```

### Example

```java
Set<String> languages = new LinkedHashSet<>();

languages.add("Java");
languages.add("Python");
languages.add("Spring");

System.out.println(languages);
// [Java, Python, Spring]
```

Adding an existing element does not create a duplicate or move its original insertion position.

### HashSet vs LinkedHashSet

| Feature | HashSet | LinkedHashSet |
|---|---|---|
| Duplicates | Not allowed | Not allowed |
| Iteration order | Not guaranteed | Insertion order |
| Internal structure | Hash table | Hash table + linked ordering |
| Memory overhead | Lower | Higher |
| Lookup | Expected \(O(1)\) | Expected \(O(1)\) |

## 8. TreeSet

`TreeSet<E>` is a sorted implementation of `NavigableSet`.

It uses a self-balancing Red-Black Tree to maintain elements in sorted order.

### Characteristics

- Stores unique elements.
- Maintains sorted order.
- Basic insertion, deletion, and search operations take \(O(\log n)\).
- Supports range and navigation operations.
- Uses natural ordering or a supplied `Comparator`.

```java
Set<Integer> numbers = new TreeSet<>();

numbers.add(30);
numbers.add(10);
numbers.add(20);

System.out.println(numbers); // [10, 20, 30]
```

### Constructors

```java
TreeSet<Integer> set1 = new TreeSet<>();

TreeSet<Integer> set2 = new TreeSet<>(
    Comparator.reverseOrder()
);

TreeSet<Integer> set3 = new TreeSet<>(
    Arrays.asList(10, 30, 20)
);
```

A custom comparator can define the ordering instead of natural ordering.

## 9. SortedSet and NavigableSet Methods

`TreeSet` implements `NavigableSet`, which extends `SortedSet`.

### SortedSet methods

| Method | Purpose |
|---|---|
| `first()` | Returns the smallest element |
| `last()` | Returns the largest element |
| `headSet(toElement)` | Returns a view of elements smaller than the endpoint |
| `tailSet(fromElement)` | Returns a view of elements greater than or equal to the starting point |
| `subSet(fromElement, toElement)` | Returns a view from the starting point (inclusive) to the endpoint (exclusive) |
| `comparator()` | Returns the comparator, or `null` when natural ordering is used |

### Example

```java
TreeSet<Integer> numbers = new TreeSet<>(
    Arrays.asList(10, 20, 30, 40, 50)
);

System.out.println(numbers.first()); // 10
System.out.println(numbers.last());  // 50

System.out.println(numbers.headSet(30)); // [10, 20]
System.out.println(numbers.tailSet(30)); // [30, 40, 50]
System.out.println(numbers.subSet(20, 40)); // [20, 30]
```

These methods return backed views, not independent copies. Changes to a view can affect the original set.

### NavigableSet methods

| Method | Purpose |
|---|---|
| `lower(e)` | Greatest element strictly less than `e` |
| `floor(e)` | Greatest element less than or equal to `e` |
| `ceiling(e)` | Smallest element greater than or equal to `e` |
| `higher(e)` | Smallest element strictly greater than `e` |
| `pollFirst()` | Retrieves and removes the first element |
| `pollLast()` | Retrieves and removes the last element |
| `descendingSet()` | Returns a reverse-order view |

Example:

```java
TreeSet<Integer> numbers = new TreeSet<>(
    Arrays.asList(10, 20, 30, 40)
);

System.out.println(numbers.lower(30));   // 20
System.out.println(numbers.floor(30));   // 30
System.out.println(numbers.ceiling(25)); // 30
System.out.println(numbers.higher(30));  // 40
```

## 10. Null Handling

| Implementation | Null support |
|---|---|
| `HashSet` | Allows one `null` |
| `LinkedHashSet` | Allows one `null` |
| `TreeSet` | Natural ordering does not support `null` |

A `TreeSet` using a custom comparator may support `null` if that comparator explicitly handles it.

For natural ordering, a `null` element cannot be compared with ordinary values and typically results in `NullPointerException`.

## 11. Comparison of Set Implementations

| Feature | HashSet | LinkedHashSet | TreeSet |
|---|---|---|---|
| Internal structure | Hash table | Hash table + linked ordering | Red-Black Tree |
| Duplicates | No | No | No |
| Ordering | None guaranteed | Insertion order | Sorted order |
| Basic operations | Expected \(O(1)\) | Expected \(O(1)\) | \(O(\log n)\) |
| Null | One allowed | One allowed | Depends on comparator; natural ordering rejects it |
| Best suited for | Uniqueness and membership checks | Uniqueness with insertion order | Uniqueness with sorted order |

## 12. Interview Quick Revision

1. **What is a Set?** A collection that does not allow duplicate elements.
2. **How does HashSet work internally?** It uses a HashMap, storing set elements as keys and a dummy `PRESENT` object as values.
3. **What is hashing?** Mapping an object to a hash value used to determine its bucket.
4. **What is a collision?** Two different elements mapping to the same bucket.
5. **How are collisions handled?** Common HashMap implementations use chaining and may treeify long buckets.
6. **What is the load factor?** The ratio of entries to table capacity.
7. **What is the default load factor commonly used by HashMap?** 0.75.
8. **What is rehashing?** Redistributing entries when the hash table resizes.
9. **HashSet vs LinkedHashSet?** No guaranteed order versus insertion order.
10. **HashSet vs TreeSet?** Expected constant-time hash-based operations versus logarithmic sorted-tree operations.
11. **What does TreeSet use internally?** A Red-Black Tree.
12. **Why must `equals()` and `hashCode()` be consistent?** Hash-based collections rely on both for correct lookup and uniqueness.
13. **Does TreeSet always reject null?** Natural ordering rejects null, but a suitable custom comparator can support it.
