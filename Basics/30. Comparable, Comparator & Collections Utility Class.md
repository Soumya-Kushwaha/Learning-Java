# Comparable, Comparator & Collections Utility Class

## 1. Comparable vs Comparator

Both interfaces define ordering between objects, but they serve different purposes.

| Comparable | Comparator |
|---|---|
| Defines natural ordering | Defines custom ordering |
| Implemented by the class being sorted | Usually defined outside the class |
| `compareTo(T other)` | `compare(T o1, T o2)` |
| `java.lang` | `java.util` |
| One natural ordering per class | Multiple sorting strategies possible |

## 2. Comparable

Implement `Comparable<T>` when a class should have a default or natural ordering.

```java
class Employee implements Comparable<Employee> {
    int id;
    String name;

    Employee(int id, String name) {
        this.id = id;
        this.name = name;
    }

    @Override
    public int compareTo(Employee other) {
        return Integer.compare(this.id, other.id);
    }
}
```

Usage:

```java
List<Employee> employees = new ArrayList<>();

Collections.sort(employees);
// or
employees.sort(null);
```

`compareTo()` contract:

- Negative: current object is smaller.
- Zero: both objects are equal in ordering.
- Positive: current object is greater.

Avoid subtraction:

```java
return this.id - other.id; // Avoid: can overflow
```

Prefer:

```java
return Integer.compare(this.id, other.id);
```

**Important:** Natural ordering should ideally be consistent with `equals()`. This is especially important when using sorted collections such as `TreeSet` and `TreeMap`.

## 3. Comparator

Use `Comparator<T>` when you need a custom ordering without modifying the class.

```java
Comparator<Employee> byName =
    (e1, e2) -> e1.name.compareTo(e2.name);

employees.sort(byName);
```

Using an anonymous class:

```java
Comparator<Employee> byId = new Comparator<>() {
    @Override
    public int compare(Employee e1, Employee e2) {
        return Integer.compare(e1.id, e2.id);
    }
};
```

### Comparator factory methods

```java
// Ascending order
Comparator<Employee> byId =
    Comparator.comparingInt(e -> e.id);

// Descending order
Comparator<Employee> byIdDesc = byId.reversed();

// String-based ordering
Comparator<Employee> byName =
    Comparator.comparing(e -> e.name);

// Multiple sorting criteria
Comparator<Employee> byDeptThenName =
    Comparator.comparing((Employee e) -> e.department)
              .thenComparing(e -> e.name);
```

Other useful methods:

| Method | Purpose |
|---|---|
| `comparing()` | Creates a comparator using a key |
| `comparingInt()` | Efficient key extraction for `int` |
| `thenComparing()` | Adds a secondary sorting criterion |
| `reversed()` | Reverses ordering |
| `naturalOrder()` | Uses natural ordering |
| `reverseOrder()` | Reverse natural ordering |
| `nullsFirst()` | Places null values first |
| `nullsLast()` | Places null values last |

Example with null handling:

```java
Comparator<String> comparator =
    Comparator.nullsLast(Comparator.naturalOrder());
```

## 4. Sorting APIs

| API | Usage |
|---|---|
| `Collections.sort(list)` | Sorts using natural ordering |
| `Collections.sort(list, comparator)` | Sorts using a comparator |
| `list.sort(comparator)` | Sorts a list |
| `Arrays.sort(array)` | Sorts an array |
| `Arrays.sort(array, comparator)` | Sorts an object array using a comparator |

Notes:

- Object sorting APIs are stable: equal elements retain their relative order.
- `List.sort(null)` uses natural ordering.
- Sorting requires elements to be mutually comparable under the selected ordering.
- `Arrays.sort()` also has overloads for primitive arrays.

## 5. Sorted Collections

`TreeSet` and `TreeMap` maintain elements or keys in sorted order.

They use:

- Natural ordering through `Comparable`, or
- A supplied `Comparator`.

**Important:** Sorted collections use the comparison result to determine ordering and equivalence. If comparison returns zero, the elements are treated as equivalent for set/map key purposes, even if `equals()` returns false.

## 6. Collections Utility Class

`java.util.Collections` is a utility class containing static methods for working with collections.

It is different from the `Collection` interface.

### Common methods

| Method | Purpose |
|---|---|
| `sort(list)` | Sorts a list |
| `reverse(list)` | Reverses list order |
| `shuffle(list)` | Randomly shuffles elements |
| `swap(list, i, j)` | Swaps two elements |
| `min(collection)` | Returns minimum element |
| `max(collection)` | Returns maximum element |
| `frequency(collection, obj)` | Counts occurrences |
| `disjoint(c1, c2)` | Checks whether collections have no common elements |
| `fill(list, obj)` | Replaces every list element |
| `copy(dest, src)` | Copies elements into an existing destination list |
| `rotate(list, distance)` | Rotates elements |
| `nCopies(n, obj)` | Returns an immutable list containing repeated references |

### Binary search

```java
List<Integer> numbers = new ArrayList<>(
    List.of(10, 20, 30, 40)
);

int index = Collections.binarySearch(numbers, 30);
```

- The list must already be sorted using the same ordering.
- Returns the index if found.
- Returns `(-(insertion point) - 1)` if not found.
- On an `ArrayList`, search is logarithmic.
- On a `LinkedList`, traversal makes the overall operation linear.

### Unmodifiable and synchronized wrappers

```java
List<String> readOnly =
    Collections.unmodifiableList(list);

List<String> synchronizedList =
    Collections.synchronizedList(new ArrayList<>());
```

- `unmodifiableList()` returns an unmodifiable view; changes through the original list can still be visible.
- `List.copyOf()` creates an unmodifiable shallow copy and rejects null elements.
- Synchronized wrappers synchronize individual operations. Iteration still requires manual synchronization on the wrapper.

## 7. Interview Quick Revision

**Q1. Comparable vs Comparator?**

Comparable defines natural ordering inside the class. Comparator defines external/custom ordering.

**Q2. Can a class have multiple Comparators?**

Yes. Different Comparator implementations can define different sorting strategies.

**Q3. What happens if `compareTo()` returns zero?**

The objects are equal in ordering. Sorted collections treat them as equivalent.

**Q4. Why use `Integer.compare()` instead of subtraction?**

Subtraction can overflow and produce an incorrect comparison result.

**Q5. Does `Collections.sort()` modify the original list?**

Yes. It sorts the supplied list in place.

**Q6. Is `Collections` an interface?**

No. It is a utility class containing static methods. `Collection` is an interface.

**Q7. Is `Collections.unmodifiableList()` the same as an immutable copy?**

No. It is an unmodifiable view of the underlying list. Changes to the original list can still be reflected.

**Q8. Can Comparator be implemented using a lambda?**

Yes. Comparator is a functional interface with one abstract method, `compare()`.

## Quick Revision

- `Comparable` → `compareTo()` → natural ordering.
- `Comparator` → `compare()` → custom ordering.
- `thenComparing()` → multiple sorting criteria.
- `reversed()` → reverse ordering.
- `TreeSet` / `TreeMap` → sorted collections.
- `Collections` → utility class for collection operations.
- `Collections.sort()` → in-place sorting.
- `Collections.binarySearch()` → requires a sorted list.
