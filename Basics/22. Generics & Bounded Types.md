# Generics & Bounded Types

## 1. What Are Generics?

**Generics** allow classes, interfaces, and methods to operate on different data types while maintaining compile-time type safety.

Instead of working with `Object` and performing manual downcasting, generics let us specify the expected type using a **type parameter**, such as `T`.

### Without Generics

```java
class Box {
    private Object value;

    public void set(Object value) {
        this.value = value;
    }

    public Object get() {
        return value;
    }
}
```

Usage:

```java
Box box = new Box();
box.set("Java");

String value = (String) box.get(); // Manual downcasting
System.out.println(value);
```

Problems:

- The box accepts any object, even if only strings are intended.
- The caller must manually cast the returned `Object`.
- An incorrect cast causes a runtime `ClassCastException`.

```java
Box box = new Box();
box.set(100);

String value = (String) box.get(); // ClassCastException at runtime
```

### With Generics

```java
class Box<T> {
    private T value;

    public void set(T value) {
        this.value = value;
    }

    public T get() {
        return value;
    }
}
```

Usage:

```java
Box<String> box = new Box<>();
box.set("Java");

String value = box.get(); // No explicit cast required
System.out.println(value);
```

Now, the compiler prevents incompatible values from being assigned:

```java
Box<String> box = new Box<>();
box.set("Java");
// box.set(100); // Compile-time error
```

### Advantages of Generics

- **Type safety:** Detects incompatible types at compile time.
- **No manual downcasting:** Values can be retrieved using the declared type.
- **Code reusability:** One implementation can work with multiple reference types.
- **Fewer runtime errors:** Helps prevent type-related `ClassCastException`s.

## 2. Generic Classes

A generic class declares one or more type parameters that can be substituted with concrete types when an object is created.

### Syntax

```java
class ClassName<T> {
    // T represents a type parameter
}
```

`T` is a placeholder for a type, not a particular Java class.

### Example: Generic Box

```java
class Box<T> {
    private T value;

    public Box(T value) {
        this.value = value;
    }

    public T getValue() {
        return value;
    }
}
```

Usage:

```java
Box<String> stringBox = new Box<>("Java");
Box<Integer> integerBox = new Box<>(100);
Box<Double> doubleBox = new Box<>(10.5);

System.out.println(stringBox.getValue());  // Java
System.out.println(integerBox.getValue()); // 100
System.out.println(doubleBox.getValue());  // 10.5
```

Each object specifies the type it stores, while the class implementation remains reusable.

### Multiple Type Parameters

A generic class can declare more than one type parameter.

```java
class Pair<T, U> {
    private T first;
    private U second;

    public Pair(T first, U second) {
        this.first = first;
        this.second = second;
    }

    public T getFirst() {
        return first;
    }

    public U getSecond() {
        return second;
    }
}
```

Usage:

```java
Pair<String, Integer> pair = new Pair<>("Age", 24);

System.out.println(pair.getFirst());  // Age
System.out.println(pair.getSecond()); // 24
```

Here, `T` and `U` represent potentially different types.

### Common Type Parameter Names

| Parameter | Conventional meaning |
|---|---|
| `T` | Type |
| `E` | Element, commonly used in collections |
| `K` | Key |
| `V` | Value |
| `N` | Number |
| `R` | Result or return type |

These are naming conventions, not Java keywords.

## 3. Generic Interfaces

Interfaces can also declare type parameters.

```java
interface Container<T> {
    void add(T value);
    T get();
}
```

An implementation specifies the type:

```java
class StringContainer implements Container<String> {
    private String value;

    @Override
    public void add(String value) {
        this.value = value;
    }

    @Override
    public String get() {
        return value;
    }
}
```

Generics are widely used by Java's Collections Framework, such as `List<String>` and `Map<String, Integer>`.

## 4. Generic Methods

A **generic method** declares its own type parameter, allowing the method to operate on different types independently of whether its enclosing class is generic.

### Syntax

```java
public static <T> void methodName(T value) {
    // Method body
}
```

The type parameter declaration `<T>` appears **before the return type**.

### Example

```java
class Printer {
    public static <T> void print(T value) {
        System.out.println(value);
    }
}
```

Usage:

```java
Printer.print("Java");
Printer.print(100);
Printer.print(10.5);
```

The same method accepts different reference types without requiring overloads for each type.

### Generic Method with Multiple Parameters

```java
public static <T, U> void printPair(T first, U second) {
    System.out.println(first + " : " + second);
}
```

Usage:

```java
printPair("Age", 24);
printPair("Score", 95.5);
```

### Generic Method Type Inference

Java can often infer a generic method's type arguments from its arguments and the surrounding context.

```java
public static <T> T identity(T value) {
    return value;
}

String text = identity("Java"); // T inferred as String
Integer number = identity(100); // T inferred as Integer
```

You can also explicitly supply type arguments when necessary:

```java
String text = Printer.<String>identity("Java");
```

Type inference reduces verbosity but does not remove compile-time type checking.

## 5. Generic Class vs Generic Method

| Feature | Generic class | Generic method |
|---|---|---|
| Declaration | `class Box<T>` | `<T> T method(T value)` |
| Scope of type parameter | Class or interface declaration | That method |
| Type determined | When the parameterized type is used | From the method invocation and context |
| Can exist in a non-generic class? | Not applicable | Yes |

A class-level type parameter is not automatically available to a static method because static members belong to the class rather than a particular parameterized instance.

A static method can declare its own type parameter:

```java
class Utility<T> {
    // T belongs to the class.

    public static <U> void print(U value) {
        System.out.println(value);
    }
}
```

## 6. Bounded Type Parameters

A **bounded type parameter** restricts which types may be used as a generic argument.

Without a bound, a type parameter such as `T` can generally represent any reference type.

Use `extends` to specify an upper bound.

### Upper Bound with a Class

```java
class Calculator<T extends Number> {
    public double square(T value) {
        return value.doubleValue() * value.doubleValue();
    }
}
```

Usage:

```java
Calculator<Integer> intCalc = new Calculator<>();
System.out.println(intCalc.square(5)); // 25.0

Calculator<Double> doubleCalc = new Calculator<>();
System.out.println(doubleCalc.square(2.5)); // 6.25

// Calculator<String> stringCalc = new Calculator<>();
// Compile-time error: String does not extend Number
```

Because `T` extends `Number`, the compiler allows methods declared by `Number`, such as `doubleValue()`.

`Integer`, `Double`, `Float`, and `Long` are valid arguments. Primitive types such as `int` and `double` are not.

### Bounded Generic Methods

Bounds can also be applied to generic methods.

```java
public static <T extends Number> double square(T value) {
    return value.doubleValue() * value.doubleValue();
}
```

Usage:

```java
System.out.println(square(4));   // 16.0
System.out.println(square(2.5)); // 6.25
```

### Multiple Bounds

A type parameter can be constrained by a class and one or more interfaces.

```java
class Animal {
    public void eat() {
        System.out.println("Eating");
    }
}

interface Swimmable {
    void swim();
}

class Fish extends Animal implements Swimmable {
    @Override
    public void swim() {
        System.out.println("Swimming");
    }
}

class AnimalProcessor<T extends Animal & Swimmable> {
    public void process(T animal) {
        animal.eat();
        animal.swim();
    }
}
```

Usage:

```java
AnimalProcessor<Fish> processor = new AnimalProcessor<>();
processor.process(new Fish());
```

The bound guarantees that `T` is both an `Animal` and `Swimmable`, so both sets of methods are available.

**Important rules:**

- Use `&` to combine bounds.
- If a class bound exists, it must come first.
- Only one class can be specified, but multiple interfaces can be specified.
- The type must satisfy every declared bound.

Example:

```java
<T extends Animal & Swimmable & Runnable>
```

Here, `Animal` is the class bound, while `Swimmable` and `Runnable` are interface bounds.

## 7. Important Limitations of Generics

### Primitive Types Are Not Allowed

Generic type arguments must be reference types, not primitives.

```java
// Box<int> box = new Box<>(); // Invalid
Box<Integer> box = new Box<>(10); // Valid
```

Use wrapper classes such as `Integer`, `Double`, and `Boolean`. Autoboxing can convert between compatible primitive values and their wrappers.

### Cannot Directly Instantiate a Type Parameter

```java
class Box<T> {
    // T value = new T(); // Invalid
}
```

The runtime does not retain enough concrete generic type information for this operation under Java's type-erasure model.

### Static Members Cannot Use a Class's Type Parameter

```java
class Box<T> {
    // static T value; // Invalid
}
```

A static member is shared at the class level, while `T` belongs to the parameterized type. A static generic method can instead declare its own type parameter.

### Generic Arrays Cannot Be Created Directly

```java
// T[] values = new T[10]; // Invalid
```

Creating arrays of a non-reifiable generic type is prohibited because arrays and generics enforce type safety differently.

### Cannot Overload Methods Solely by Generic Arguments

```java
// void process(List<String> values) {}
// void process(List<Integer> values) {} // Same erased signature
```

Both parameter types erase to `List`, so these declarations conflict.

## 8. Important Gotchas

- **Generics improve compile-time safety:** They prevent many invalid assignments before execution, but cannot guarantee that every possible runtime type error is eliminated.
- **`T` is not a keyword:** It is a conventional name for a type parameter.
- **`extends` applies to class and interface bounds:** It does not mean that the bound must be a class; interfaces can also be used.
- **A generic class is not automatically a generic method:** Each has its own type-parameter scope.
- **Static methods need their own type parameters:** A static method cannot directly use the class's type parameter.
- **Generics work with reference types:** Use wrapper classes for primitives.

## 9. Interview Quick Revision

- **What are generics?** A mechanism for writing reusable, type-safe classes, interfaces, and methods.
- **Why use generics instead of `Object`?** They provide compile-time type checking and avoid manual downcasting.
- **What is a generic class?** A class whose declaration includes one or more type parameters.
- **What is a generic method?** A method that declares its own type parameter.
- **What is type inference?** The compiler's ability to determine type arguments from context.
- **What is a bounded type parameter?** A type parameter restricted to types satisfying a specified bound.
- **What does `T extends Number` mean?** `T` must be `Number` or a subtype of `Number`.
- **How are multiple bounds declared?** With `&`, placing any class bound before interface bounds.
- **Can generics use `int` directly?** No. Use `Integer`.
- **Why can't `new T()` be used?** The concrete type is not available in the required form at runtime because of type erasure.
