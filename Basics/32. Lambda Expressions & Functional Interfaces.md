# Lambda Expressions & Functional Interfaces

## 1. Why Lambda Expressions?

Java traditionally uses objects to represent both data and behavior.

If we want to pass behavior (for example, sorting logic) to a method, we need an object implementing an interface such as `Comparator`.

Java evolved through a few approaches:

1. **Concrete class** — create a separate class implementing the interface.
2. **Anonymous class** — implement the interface inline without naming the class.
3. **Lambda expression** — represent the implementation of a functional interface concisely.

Lambdas reduce boilerplate when passing small pieces of behavior.

## 2. Functional Interface

A **functional interface** is an interface with exactly one abstract method (SAM — Single Abstract Method).

```java
@FunctionalInterface
interface Calculator {
    int calculate(int a, int b);
}
```

`@FunctionalInterface` is optional, but recommended. The compiler verifies that the interface satisfies the functional-interface contract.

An interface can still have:
- Any number of `default` methods.
- Any number of `static` methods.
- Private helper methods.
- Methods matching public methods of `Object`, without affecting its functional-interface status.

Examples from the JDK:
- `Runnable` — `run()`
- `Comparator<T>` — `compare()`
- `Callable<V>` — `call()`
- `Predicate<T>` — `test()`

## 3. Three Ways to Implement a Functional Interface

Consider a `Calculator` functional interface.

**A. Concrete implementation**

```java
class Addition implements Calculator {
    @Override
    public int calculate(int a, int b) {
        return a + b;
    }
}

Calculator calculator = new Addition();
```

**B. Anonymous class**

```java
Calculator calculator = new Calculator() {
    @Override
    public int calculate(int a, int b) {
        return a + b;
    }
};
```

**C. Lambda expression**

```java
Calculator calculator = (a, b) -> a + b;
```

The lambda provides the implementation of the interface's single abstract method.

## 4. Lambda Expression Syntax

General syntax:

```java
(parameters) -> expression
```

Or, for a block body:

```java
(parameters) -> {
    // statements
    return result;
}
```

Examples:

```java
// No parameters
Runnable task = () -> System.out.println("Running");

// One parameter: parentheses are optional
Consumer<String> printer = name -> System.out.println(name);

// Multiple parameters
Calculator addition = (a, b) -> a + b;

// Block body with explicit return
Calculator multiplication = (a, b) -> {
    int result = a * b;
    return result;
};
```

Rules:
- A single expression is returned implicitly when the target method has a return value.
- A block body needs an explicit `return` when the method returns a value.
- A block body for a `void` method does not need a return statement.
- Parameter types can usually be inferred from the target functional interface.
- Parentheses can be omitted for exactly one parameter.

## 5. Target Typing and Type Inference

A lambda expression does not have a standalone functional-interface type. Its type is inferred from the **target type** provided by the surrounding context.

```java
Calculator addition = (a, b) -> a + b;
```

The compiler knows that:
- The target type is `Calculator`.
- Its abstract method is `calculate(int, int)`.
- Both lambda parameters are therefore `int`.
- The result must be compatible with `int`.

The same lambda can be used with another compatible functional interface:

```java
Comparator<Integer> comparator = (a, b) -> a - b;
```

The target interface determines the parameter types and expected return type.

If the compiler cannot infer the types from context, explicitly declaring parameter types may help.

## 6. Lambdas as Method Arguments

Lambdas are especially useful when a method accepts a functional interface.

```java
List<String> names = List.of("Riya", "Aman", "Zoya");

names.forEach(name -> System.out.println(name));
```

Sorting with a custom comparator:

```java
List<Integer> numbers = new ArrayList<>(List.of(5, 2, 8, 1));

numbers.sort((a, b) -> Integer.compare(a, b));
```

The behavior is passed directly to the method instead of being wrapped in a separate named class.

## 7. Lambda vs Anonymous Class

| Aspect | Lambda | Anonymous class |
|---|---|---|
| Syntax | Concise | More verbose |
| Main purpose | Implement functional interface behavior | Create an inline class implementation |
| `this` | Refers to enclosing instance | Refers to anonymous class instance |
| Scope | Does not introduce a new `this` scope | Introduces its own `this` |
| Methods | Implements the functional interface's SAM | Can implement multiple methods and override inherited methods |

Use a lambda for a small behavior implementation. Use an anonymous class when you need a more substantial inline class implementation.

## 8. Variable Capture

A lambda can access local variables from its enclosing scope if they are **final or effectively final**.

```java
int multiplier = 2;

Function<Integer, Integer> multiply =
        number -> number * multiplier;
```

This is valid because `multiplier` is not reassigned.

This is invalid:

```java
int multiplier = 2;

Function<Integer, Integer> multiply =
        number -> number * multiplier;

multiplier = 3; // Compilation error
```

The effectively-final restriction applies to captured local variables. It does not mean that an object referenced by a captured variable must itself be immutable.

## 9. Important Limitations and Gotchas

- A lambda requires a target functional interface; it cannot be assigned to `Object` directly without an appropriate cast or target type.
- A lambda cannot implement an interface with multiple unrelated abstract methods.
- A lambda's parameter and return types must match the functional interface's abstract method.
- Checked exceptions must be compatible with the functional interface method's `throws` declaration.
- Captured local variables must be final or effectively final.

## 10. Interview Quick Revision

**What is a functional interface?**

An interface with exactly one abstract method. It can be implemented using a lambda expression or method reference.

**Why were lambdas introduced?**

To reduce boilerplate and make it easier to pass behavior as an argument.

**What is SAM?**

Single Abstract Method — the one abstract method that a lambda implements.

**What is target typing?**

The compiler infers a lambda's parameter and return types from the functional interface expected by its context.

**Can a functional interface have default and static methods?**

Yes. They do not count towards its single abstract method.

**Can a lambda access local variables?**

Yes, provided captured local variables are final or effectively final.

**Does `this` inside a lambda refer to the lambda itself?**

No. It refers to the enclosing instance.
