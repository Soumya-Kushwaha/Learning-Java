# Built-in Functional Interfaces & Method References

Java provides built-in functional interfaces in `java.util.function` to represent common types of behavior.

These interfaces are widely used with lambdas, Streams, collections, and asynchronous APIs.

## 1. Core Functional Interfaces

| Interface | Abstract method | Input | Output | Typical use |
|---|---|---|---|---|
| `Predicate<T>` | `test(T)` | T | boolean | Condition/check |
| `Function<T, R>` | `apply(T)` | T | R | Transform value |
| `Consumer<T>` | `accept(T)` | T | void | Perform an action |
| `Supplier<T>` | `get()` | None | T | Supply a value |
| `UnaryOperator<T>` | `apply(T)` | T | T | Transform same type |
| `BinaryOperator<T>` | `apply(T, T)` | T, T | T | Combine two values |

### Predicate<T>

Represents a condition that returns `boolean`.

```java
Predicate<Integer> isEven = number -> number % 2 == 0;

System.out.println(isEven.test(4)); // true
System.out.println(isEven.test(5)); // false
```

### Function<T, R>

Accepts one value and returns a transformed value.

```java
Function<String, Integer> length = text -> text.length();

System.out.println(length.apply("Java")); // 4
```

### Consumer<T>

Accepts a value and performs an operation without returning a result.

```java
Consumer<String> printer = text -> System.out.println(text);

printer.accept("Java");
```

### Supplier<T>

Takes no arguments and supplies a value.

```java
Supplier<Double> randomValue = () -> Math.random();

System.out.println(randomValue.get());
```

### UnaryOperator<T>

A specialization of `Function<T, T>` where input and output have the same type.

```java
UnaryOperator<Integer> square = number -> number * number;

System.out.println(square.apply(5)); // 25
```

### BinaryOperator<T>

A specialization of `BiFunction<T, T, T>` where both inputs and the output have the same type.

```java
BinaryOperator<Integer> sum = (a, b) -> a + b;

System.out.println(sum.apply(10, 20)); // 30
```

## 2. Bi-Functional Interfaces

Bi-functional interfaces accept two input arguments.

| Interface | Abstract method | Inputs | Output |
|---|---|---|---|
| `BiPredicate<T, U>` | `test(T, U)` | T, U | boolean |
| `BiFunction<T, U, R>` | `apply(T, U)` | T, U | R |
| `BiConsumer<T, U>` | `accept(T, U)` | T, U | void |

Examples:

```java
BiPredicate<String, Integer> hasLength =
        (text, length) -> text.length() == length;

BiFunction<Integer, Integer, Integer> add =
        (a, b) -> a + b;

BiConsumer<String, Integer> printDetails =
        (name, age) -> System.out.println(name + ": " + age);
```

There is no standard `BiSupplier` because a supplier takes no input arguments.

## 3. Primitive Functional Interfaces

Generic functional interfaces use reference types. Using primitives with them can involve boxing and unboxing.

For example:

```java
Predicate<Integer> isPositive = number -> number > 0;
```

The `Integer` value may need to be unboxed to `int` for the comparison.

Java provides primitive-specialized interfaces to avoid unnecessary boxing and unboxing.

Common examples:

| Interface | Input | Output | Abstract method |
|---|---|---|---|
| `IntPredicate` | int | boolean | `test(int)` |
| `IntFunction<R>` | int | R | `apply(int)` |
| `IntUnaryOperator` | int | int | `applyAsInt(int)` |
| `IntBinaryOperator` | int, int | int | `applyAsInt(int, int)` |
| `ToIntFunction<T>` | T | int | `applyAsInt(T)` |
| `ToIntBiFunction<T, U>` | T, U | int | `applyAsInt(T, U)` |
| `IntConsumer` | int | void | `accept(int)` |
| `IntSupplier` | None | int | `getAsInt()` |

Equivalent specializations exist for `long` and `double`, such as:
- `LongPredicate`, `LongUnaryOperator`, `LongSupplier`
- `DoublePredicate`, `DoubleUnaryOperator`, `DoubleSupplier`

There are also conversion interfaces such as `IntToLongFunction`, `IntToDoubleFunction`, and `ToDoubleFunction<T>`.

Example:

```java
IntPredicate isEven = number -> number % 2 == 0;

IntUnaryOperator square = number -> number * number;

ToIntFunction<String> getLength = text -> text.length();
```

**Interview point:** Primitive specializations can reduce boxing/unboxing overhead, especially in performance-sensitive operations and large data-processing pipelines.

## 4. Method References (`::`)

A method reference is a concise alternative to a lambda when the lambda simply calls an existing method.

```java
// Lambda
Consumer<String> printer = text -> System.out.println(text);

// Method reference
Consumer<String> printerRef = System.out::println;
```

The method reference must be compatible with the target functional interface's abstract method.

### Four common forms

**1. Static method reference**

Syntax:

```java
ClassName::staticMethod
```

```java
Function<String, Integer> parser = Integer::parseInt;
```

Equivalent lambda:

```java
Function<String, Integer> parser = text -> Integer.parseInt(text);
```

**2. Instance method reference of a particular object**

Syntax:

```java
object::instanceMethod
```

```java
Consumer<String> printer = System.out::println;
```

Equivalent lambda:

```java
Consumer<String> printer = text -> System.out.println(text);
```

**3. Instance method reference of an arbitrary object of a particular type**

Syntax:

```java
ClassName::instanceMethod
```

```java
Function<String, String> upperCase = String::toUpperCase;
```

Equivalent lambda:

```java
Function<String, String> upperCase = text -> text.toUpperCase();
```

The first lambda argument becomes the receiver object.

**4. Constructor reference**

Syntax:

```java
ClassName::new
```

```java
Supplier<ArrayList<String>> listFactory = ArrayList::new;
```

Equivalent lambda:

```java
Supplier<ArrayList<String>> listFactory = () -> new ArrayList<>();
```

A constructor reference can also accept arguments if the target functional interface expects them:

```java
Function<String, StringBuilder> builderFactory = StringBuilder::new;
```

## 5. Function Composition

Function composition means combining smaller functions to create a sequence of operations.

### Function.andThen()

Executes the current function first, then the supplied function.

```java
Function<Integer, Integer> multiplyByTwo =
        number -> number * 2;

Function<Integer, Integer> addThree =
        number -> number + 3;

Function<Integer, Integer> result =
        multiplyByTwo.andThen(addThree);

System.out.println(result.apply(5)); // 13
```

Execution:

```text
5 -> multiplyByTwo -> 10 -> addThree -> 13
```

### Function.compose()

Executes the supplied function first, then the current function.

```java
Function<Integer, Integer> result =
        multiplyByTwo.compose(addThree);

System.out.println(result.apply(5)); // 16
```

Execution:

```text
5 -> addThree -> 8 -> multiplyByTwo -> 16
```

| Method | Execution order |
|---|---|
| `f.andThen(g)` | f, then g |
| `f.compose(g)` | g, then f |

Both methods return a new composed function; they do not modify the original functions.

## 6. Predicate Composition

`Predicate<T>` provides methods to combine conditions.

### and()

Both conditions must be true.

```java
Predicate<Integer> positive = number -> number > 0;
Predicate<Integer> even = number -> number % 2 == 0;

Predicate<Integer> positiveEven = positive.and(even);

System.out.println(positiveEven.test(8)); // true
```

### or()

At least one condition must be true.

```java
Predicate<Integer> condition = positive.or(even);
```

### negate()

Reverses the result of a predicate.

```java
Predicate<Integer> notPositive = positive.negate();

System.out.println(notPositive.test(-5)); // true
```

`and()` and `or()` use short-circuit evaluation:
- `and()` does not evaluate the second predicate if the first is false.
- `or()` does not evaluate the second predicate if the first is true.

## 7. Consumer Composition

`Consumer<T>` provides `andThen()` to chain actions.

```java
Consumer<String> print =
        text -> System.out.println(text);

Consumer<String> printUpper =
        text -> System.out.println(text.toUpperCase());

Consumer<String> combined = print.andThen(printUpper);

combined.accept("java");
```

The first consumer runs before the second.

## 8. Common Practical Examples

**Sorting with Comparator**

```java
List<String> names = new ArrayList<>(
        List.of("Riya", "Aman", "Zoya")
);

names.sort(Comparator.comparing(String::length));
```

**Filtering with Predicate**

```java
List<Integer> numbers = List.of(1, 2, 3, 4, 5, 6);

Predicate<Integer> isEven = number -> number % 2 == 0;

numbers.stream()
       .filter(isEven)
       .forEach(System.out::println);
```

**Transforming with Function**

```java
Function<String, String> normalize =
        String::toUpperCase;
```

**Supplying a default value**

```java
Supplier<String> defaultName = () -> "Unknown";
```

These interfaces are commonly used with the Stream API, which is covered separately.

## 9. Interview Questions

**What is the difference between `Predicate` and `Function`?**

`Predicate<T>` returns a boolean. `Function<T, R>` transforms an input into a result.

**What is the difference between `Consumer` and `Supplier`?**

`Consumer<T>` accepts an input and returns nothing. `Supplier<T>` accepts no input and returns a value.

**What is the difference between `Function` and `UnaryOperator`?**

`Function<T, R>` can have different input and output types. `UnaryOperator<T>` takes and returns the same type.

**Why use primitive functional interfaces?**

To avoid unnecessary boxing and unboxing when working with primitive values.

**What is a method reference?**

A shorthand for a lambda that calls an existing method or constructor.

**What is the difference between `andThen()` and `compose()`?**

`andThen()` executes the current function before the supplied function. `compose()` executes the supplied function first.

**Are `Predicate.and()` and `Predicate.or()` short-circuiting?**

Yes. They follow the same short-circuit behavior as `&&` and `||`.

## 10. Quick Revision

| Concept | Remember |
|---|---|
| `Predicate<T>` | T → boolean |
| `Function<T, R>` | T → R |
| `Consumer<T>` | T → void |
| `Supplier<T>` | () → T |
| `UnaryOperator<T>` | T → T |
| `BinaryOperator<T>` | (T, T) → T |
| `BiPredicate<T, U>` | (T, U) → boolean |
| `BiFunction<T, U, R>` | (T, U) → R |
| `BiConsumer<T, U>` | (T, U) → void |
| `andThen()` | Current operation first |
| `compose()` | Supplied operation first |
| `::` | Method/constructor reference |

**Package:** `java.util.function`

**Core takeaway:** Functional interfaces define the contract for behavior; lambdas and method references provide concise implementations of that behavior.
