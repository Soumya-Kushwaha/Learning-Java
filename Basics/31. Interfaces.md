# Java Interfaces

## 1. What Is an Interface?

An interface defines a **contract** that specifies what a class must do, without prescribing its complete implementation.

- Defines behavior that implementing classes must provide.
- Supports abstraction and polymorphism.
- Allows a class to implement multiple interfaces.
- Helps achieve loose coupling through programming to abstractions.

```java
interface Payment {
    void pay(double amount);
}

class UpiPayment implements Payment {
    @Override
    public void pay(double amount) {
        System.out.println("Paid using UPI");
    }
}

class CardPayment implements Payment {
    @Override
    public void pay(double amount) {
        System.out.println("Paid using Card");
    }
}
```

```java
Payment payment = new UpiPayment();
payment.pay(500);
```

The reference type is `Payment`, but the implementation is selected at runtime based on the actual object. This is runtime polymorphism.

## 2. Interface Implementation Rules

- A class uses `implements` to implement an interface.
- An implementing class must implement all inherited abstract methods unless the class itself is abstract.
- A class can implement multiple interfaces.
- An interface can extend one or more interfaces.
- An interface cannot be instantiated directly.

```java
interface Printable {
    void print();
}

interface Scannable {
    void scan();
}

class Machine implements Printable, Scannable {
    public void print() {
        System.out.println("Printing");
    }

    public void scan() {
        System.out.println("Scanning");
    }
}
```

### Interface Extending Another Interface

```java
interface A {
    void methodA();
}

interface B extends A {
    void methodB();
}

class Demo implements B {
    public void methodA() {}

    public void methodB() {}
}
```

`B` inherits the contract of `A`, so `Demo` must implement both methods.

## 3. Variables in Interfaces

All variables declared in an interface are implicitly:

- `public`
- `static`
- `final`

They are constants, not instance variables.

```java
interface Config {
    int MAX_RETRIES = 3;
}
```

Equivalent declaration:

```java
public static final int MAX_RETRIES = 3;
```

Access:

```java
System.out.println(Config.MAX_RETRIES);
```

You cannot modify an interface variable after initialization.

## 4. Multiple Inheritance Through Interfaces

Java does not support multiple inheritance of classes.

However, a class can implement multiple interfaces.

```java
interface Camera {
    void click();
}

interface MusicPlayer {
    void playMusic();
}

class Smartphone implements Camera, MusicPlayer {
    public void click() {}

    public void playMusic() {}
}
```

This allows a class to combine multiple behavioral contracts without inheriting state and implementation from multiple classes.

## 5. Default Methods (Java 8)

Before Java 8, interfaces primarily defined abstract methods.

Java 8 introduced **default methods**, which allow interfaces to provide method implementations.

```java
interface Vehicle {
    void start();

    default void stop() {
        System.out.println("Vehicle stopped");
    }
}
```

An implementing class:
- Can use the default implementation directly.
- Can override the default method with its own implementation.

### Why Were Default Methods Introduced?

They allow interfaces to evolve by adding new methods without forcing every existing implementing class to implement those methods.

For example, a new default method can be added to an existing interface while preserving compatibility with existing implementations.

## 6. Static Methods in Interfaces (Java 8)

Interfaces can also contain static methods with implementations.

```java
interface Utility {
    static void display() {
        System.out.println("Utility method");
    }
}
```

Call using the interface name:

```java
Utility.display();
```

Important:
- Static interface methods belong to the interface.
- They are not inherited as instance methods by implementing classes.
- They are called using the interface name.

## 7. Default Method Conflict — Diamond Problem

Consider two interfaces defining the same default method.

```java
interface A {
    default void show() {
        System.out.println("A");
    }
}

interface B {
    default void show() {
        System.out.println("B");
    }
}
```

A class implementing both interfaces must resolve the conflict.

```java
class Demo implements A, B {
    @Override
    public void show() {
        A.super.show();
        // Or: B.super.show();
        // Or provide a completely new implementation.
    }
}
```

The class must override `show()` because Java cannot decide which interface implementation to use.

### Calling a Specific Interface's Default Method

Syntax:

```java
InterfaceName.super.methodName();
```

Example:

```java
A.super.show();
```

This explicitly invokes the default implementation from interface `A`.

## 8. Method Resolution Priority

When a class inherits or implements methods with the same signature, Java follows these important rules:

1. **Class method wins over interface default method.**
2. A more specific subinterface's default method wins over a less specific parent interface's default method.
3. If two unrelated interfaces provide conflicting default methods, the implementing class must override the method.

### Class Method vs Interface Default Method

```java
interface A {
    default void show() {
        System.out.println("Interface");
    }
}

class Parent {
    public void show() {
        System.out.println("Class");
    }
}

class Child extends Parent implements A {}
```

```java
new Child().show(); // Class
```

The inherited class method takes priority over the interface default method.

## 9. Interface vs Abstract Class

| Feature | Interface | Abstract Class |
|---|---|---|
| Purpose | Defines a behavioral contract | Provides a common base and shared implementation |
| Methods | Abstract, default, static, private | Abstract and concrete |
| Variables | Implicitly `public static final` | Instance and static variables with different access modifiers |
| Constructor | Not allowed | Allowed |
| Multiple inheritance | A class can implement multiple interfaces | A class can extend only one class |
| Access modifiers | Abstract methods are implicitly public | Supports public, protected, and private methods |
| State | No instance fields | Can maintain instance state |
| Inheritance keyword | `implements` | `extends` |

**Choosing between them:**
- Use an interface for a `can-do` capability or contract.
- Use an abstract class when related classes need shared state, constructors, or common implementation.

## 10. Functional Interfaces

A functional interface contains exactly **one abstract method (SAM)**.

SAM = Single Abstract Method.

It can be implemented using a lambda expression or method reference.

```java
@FunctionalInterface
interface Calculator {
    int add(int a, int b);
}
```

Lambda implementation:

```java
Calculator calculator = (a, b) -> a + b;

System.out.println(calculator.add(10, 20));
```

### @FunctionalInterface

- Optional annotation.
- Tells the compiler to enforce the functional-interface constraint.
- Compilation fails if the interface has multiple unrelated abstract methods.

An interface can still have:
- Any number of default methods.
- Any number of static methods.
- Methods corresponding to public methods of `Object`, such as `equals()`.

These do not count as additional abstract methods for the functional-interface rule.

### Built-in Functional Interfaces

Common interfaces from `java.util.function`:

| Interface | Abstract method | Purpose |
|---|---|---|
| `Predicate<T>` | `test(T)` | Takes input and returns boolean |
| `Function<T, R>` | `apply(T)` | Takes input and returns output |
| `Consumer<T>` | `accept(T)` | Takes input and returns nothing |
| `Supplier<T>` | `get()` | Supplies a value without input |
| `UnaryOperator<T>` | `apply(T)` | Takes and returns the same type |
| `BinaryOperator<T>` | `apply(T, T)` | Takes two values of the same type and returns that type |

Example:

```java
Predicate<Integer> isEven = n -> n % 2 == 0;

Function<String, Integer> length = s -> s.length();

Consumer<String> printer = s -> System.out.println(s);

Supplier<Double> randomValue = () -> Math.random();
```

## 11. Marker Interfaces

A marker interface is an interface with no methods or fields. It marks a class with a particular capability or semantic property.

Examples:

| Marker Interface | Purpose |
|---|---|
| `Serializable` | Indicates that objects can participate in Java serialization |
| `Cloneable` | Indicates that `Object.clone()` can perform field copying for the class |
| `RandomAccess` | Indicates that a list supports fast random access |

Example:

```java
class Employee implements Serializable {
    private int id;
}
```

**Important:** A marker interface does not automatically implement behavior. It provides metadata that APIs or frameworks can inspect.

`Cloneable` is a special case: `Object.clone()` checks whether the object's class implements it; otherwise, it throws `CloneNotSupportedException`.

## 12. Private Methods in Interfaces (Java 9)

Java 9 introduced private methods in interfaces to help reuse code between default and static methods.

```java
interface Logger {
    default void info(String message) {
        log("INFO", message);
    }

    default void error(String message) {
        log("ERROR", message);
    }

    private void log(String level, String message) {
        System.out.println(level + ": " + message);
    }
}
```

- Private interface methods have implementations.
- They cannot be accessed by implementing classes.
- They help avoid duplicate code within an interface.
- They can be static or instance methods.

## 13. Important Interface Rules

- An interface cannot be instantiated.
- An interface cannot have constructors.
- Interface fields are implicitly `public static final`.
- Abstract interface methods are implicitly `public abstract`.
- Default and static methods must have method bodies.
- A class can implement multiple interfaces.
- An interface can extend multiple interfaces.
- A class implementing an interface must implement its abstract methods unless it is abstract.
- Static interface methods are called through the interface name.
- Conflicting default methods must be resolved by the implementing class.
- Private interface methods are available from Java 9.

## 14. Frequently Asked Interview Questions

**Q1. Why do we need interfaces?**

To define contracts, achieve abstraction, support polymorphism, and reduce coupling between implementations and consumers.

**Q2. Can an interface have a constructor?**

No. Interfaces cannot be instantiated and do not have constructors.

**Q3. Can an interface extend multiple interfaces?**

Yes.

```java
interface C extends A, B {}
```

**Q4. Can a class implement multiple interfaces?**

Yes. This is Java's way of supporting multiple inheritance of type/contracts.

**Q5. Can an interface have concrete methods?**

Yes. Default, static, and private methods can have implementations.

**Q6. Can we override a default method?**

Yes. An implementing class can override it.

**Q7. Can static interface methods be overridden?**

No. They belong to the interface and are not inherited as instance methods.

**Q8. What happens when two interfaces have the same default method?**

The implementing class must override that method and resolve the conflict.

**Q9. What happens if a superclass and an interface have the same method?**

The inherited class method takes priority over the interface default method.

**Q10. Can an interface have multiple abstract methods and still be functional?**

No. A functional interface must have exactly one abstract method, considering the functional-interface rules.

**Q11. Can a functional interface have default and static methods?**

Yes. They do not count as additional abstract methods.

**Q12. What is a marker interface?**

An interface without methods that marks a class with a particular property or capability.

**Q13. Difference between default and static interface methods?**

- Default methods are instance methods and can be overridden by implementing classes.
- Static methods belong to the interface and are called using the interface name.

**Q14. Why were default methods introduced in Java 8?**

To allow interfaces to evolve by adding methods with implementations without breaking existing implementing classes.
