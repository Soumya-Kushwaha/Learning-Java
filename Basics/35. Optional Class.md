# Optional Class

`Optional<T>` was introduced in Java 8 as a container that may or may not hold a non-null value.

It makes the possibility of a missing result explicit and encourages callers to handle that case.

**Primary purpose:** Represent an optional return value instead of returning `null`.

## 1. The Null Problem

Traditional code often requires repeated null checks:

```java
String city = null;

if (user != null) {
    Address address = user.getAddress();

    if (address != null) {
        city = address.getCity();
    }
}
```

Nested null checks make code harder to read and maintain.

Optional provides methods to express these operations more clearly.

## 2. Creating Optional Objects

### Optional.of()

Creates an Optional containing a non-null value.

```java
Optional<String> name = Optional.of("Java");
```

Passing `null` throws `NullPointerException`.

### Optional.ofNullable()

Creates an Optional that may be empty.

```java
Optional<String> name = Optional.ofNullable(null);
```

### Optional.empty()

Creates an empty Optional.

```java
Optional<String> name = Optional.empty();
```

| Method | Behavior |
|---|---|
| `of(value)` | Requires non-null value |
| `ofNullable(value)` | Empty if value is null |
| `empty()` | Creates an empty Optional |

## 3. Checking and Accessing Values

### isPresent()

Checks whether a value exists.

```java
if (name.isPresent()) {
    System.out.println(name.get());
}
```

### isEmpty()

Returns true when no value exists. Available since Java 11.

```java
if (name.isEmpty()) {
    System.out.println("No value");
}
```

### get()

Returns the contained value.

```java
String value = name.get();
```

Calling `get()` on an empty Optional throws `NoSuchElementException`.

Avoid using `get()` without first establishing that a value exists. Prefer the other access methods where possible.

### ifPresent()

Executes a `Consumer` only when a value exists.

```java
name.ifPresent(value -> System.out.println(value));
```

Method reference:

```java
name.ifPresent(System.out::println);
```

### ifPresentOrElse()

Executes one action if a value exists and another if it is absent. Available since Java 9.

```java
name.ifPresentOrElse(
        System.out::println,
        () -> System.out.println("No value")
);
```

## 4. Default Values and Exceptions

### orElse()

Returns the contained value or a fallback value.

```java
String result = name.orElse("Unknown");
```

**Important:** The fallback expression is evaluated eagerly, even when the Optional contains a value.

```java
String result = name.orElse(getDefaultName());
```

`getDefaultName()` is evaluated before `orElse()` is invoked.

### orElseGet()

Accepts a `Supplier` and evaluates it only when the Optional is empty.

```java
String result = name.orElseGet(() -> getDefaultName());
```

| Method | Fallback evaluation |
|---|---|
| `orElse(value)` | Eager |
| `orElseGet(supplier)` | Lazy |

Use `orElseGet()` when fallback computation is expensive or has side effects.

### orElseThrow()

Throws an exception if the Optional is empty.

```java
String result = name.orElseThrow();
```

Or provide an exception supplier:

```java
String result = name.orElseThrow(
        () -> new IllegalArgumentException("Name not found")
);
```

## 5. Transforming Optional

Optional provides methods similar to Stream operations.

### map()

Transforms the contained value if present.

```java
Optional<String> name = Optional.of("java");

Optional<String> upper = name.map(String::toUpperCase);
```

If the Optional is empty, the mapping function is not executed and the result remains empty.

If the mapping function returns `null`, the result is also empty.

### flatMap()

Used when the mapping function already returns an Optional.

```java
Optional<User> user = findUser();

Optional<Address> address = user.flatMap(User::getAddress);
```

If `getAddress()` returns `Optional<Address>`, `flatMap()` avoids creating a nested `Optional<Optional<Address>>`.

**map vs flatMap**

| map() | flatMap() |
|---|---|
| Mapping function returns a value | Mapping function returns an Optional |
| Wraps the result in Optional | Does not create a nested Optional |
| `Function<T, R>` | `Function<T, Optional<R>>` |

### filter()

Retains the value only if it satisfies the predicate.

```java
Optional<Integer> number = Optional.of(10);

Optional<Integer> result = number.filter(n -> n > 5);
```

If the Optional is empty or the predicate returns false, the result is empty.

## 6. Combining Optional with Streams

Optional is useful when a lookup may not return a value.

```java
Optional<Employee> employee = findEmployeeById(101);

employee.map(Employee::getName)
        .ifPresent(System.out::println);
```

A Stream can also contain Optional results.

For example, filtering out missing values:

```java
List<Optional<String>> values = List.of(
        Optional.of("Java"),
        Optional.empty(),
        Optional.of("Spring")
);

List<String> result = values.stream()
        .flatMap(Optional::stream)
        .toList();
```

`Optional.stream()` was introduced in Java 9. It converts:
- A present Optional into a stream containing one element.
- An empty Optional into an empty stream.

## 7. Practical Example: Avoiding Nested Null Checks

Suppose a user may or may not have an address.

```java
Optional<User> user = findUser();

Optional<String> city = user
        .flatMap(User::getAddress)
        .map(Address::getCity);
```

This assumes `getAddress()` returns `Optional<Address>`.

If the user or address is missing, the final Optional is empty rather than requiring nested null checks.

## 8. Best Practices

- Prefer Optional as a method return type when a result may be absent.
- Use `Optional.ofNullable()` when wrapping a value that may be null.
- Avoid calling `get()` without checking presence.
- Prefer `map()` and `flatMap()` for transformations.
- Use `orElseGet()` for expensive fallback computations.
- Do not use Optional merely to replace every nullable field or variable.
- Avoid using Optional as a field in ordinary domain objects or as a method parameter unless there is a clear API-design reason.
- Do not return `null` from a method declared to return Optional. Return `Optional.empty()` instead.

Optional is not a replacement for every null check and does not eliminate all possible `NullPointerException`s. It helps make absence explicit at API boundaries.

## 9. Optional vs Stream

| Optional | Stream |
|---|---|
| Represents zero or one value | Represents a sequence of zero or more values |
| `map()` transforms one value | `map()` transforms each element |
| `flatMap()` avoids nested Optionals | `flatMap()` flattens nested streams |
| `orElse()` provides a fallback | `findFirst()` / `findAny()` may return Optional |
| `ifPresent()` performs an action if present | `forEach()` performs an action for each element |

## 10. Interview Quick Revision

**What is Optional?**

A container object that may contain a non-null value or be empty. It is commonly used as a method return type to represent an absent result.

**Difference between of() and ofNullable()?**

`of()` rejects null. `ofNullable()` returns an empty Optional for null.

**Difference between orElse() and orElseGet()?**

`orElse()` evaluates its fallback eagerly. `orElseGet()` invokes a Supplier only when the Optional is empty.

**Difference between map() and flatMap()?**

`map()` wraps a mapped value in Optional. `flatMap()` expects an Optional-returning function and avoids nested Optionals.

**What happens when get() is called on an empty Optional?**

It throws `NoSuchElementException`.

**Can Optional contain null?**

A properly constructed Optional never represents a present-null value. `of(null)` throws; `ofNullable(null)` returns empty.

**Should Optional be used for every nullable field?**

No. Its primary intended use is representing potentially absent return values.

### Quick Revision

- `of()` → non-null value required.
- `ofNullable()` → null becomes empty.
- `empty()` → empty Optional.
- `isPresent()` / `isEmpty()` → check presence.
- `ifPresent()` → execute action if present.
- `orElse()` → eager fallback.
- `orElseGet()` → lazy fallback.
- `orElseThrow()` → throw if empty.
- `map()` → transform value.
- `flatMap()` → transform without nested Optional.
- `filter()` → retain only if condition matches.
- `Optional.stream()` → convert to zero-or-one-element Stream (Java 9+).
