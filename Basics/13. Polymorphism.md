# Polymorphism

Polymorphism allows the same operation or reference type to produce different behavior depending on the method signature or runtime object.

## Compile-Time Polymorphism: Overloading
- Same method name, different parameter lists.
- Resolved by the compiler using the declared argument types and overload-resolution rules.
- Changing only the return type does not create a valid overload.

```java
void print(int value) {}
void print(String value) {}
```

## Runtime Polymorphism: Overriding
- A subclass provides an implementation compatible with an inherited instance method.
- The implementation is selected at runtime based on the actual object type.

```java
Animal animal = new Dog();
animal.sound(); // Bark
```

The reference type determines which members are accessible at compile time; the runtime object's type determines the overridden instance implementation.

## Overriding Rules & Gotchas
- **Static methods:** Not overridden; a matching subclass declaration hides the superclass method.
- **Private methods:** Not overridden because they are not inherited as accessible methods.
- **Final methods:** Cannot be overridden.
- Fields / variables are not polymorphic.
- Overriding cannot reduce access visibility.
- The return type must be the same or covariant for reference types.
- Use `@Override` to catch signature mistakes.

## Overloading vs. Overriding

| Overloading | Overriding |
|---|---|
| Different parameter lists | Compatible inherited method signature |
| Compile-time resolution | Runtime dispatch for instance methods |
| Can occur in one class | Requires inheritance or interface implementation |
| Return type alone is insufficient | Covariant return types are allowed |
